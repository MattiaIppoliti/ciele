Ciele propose trois interfaces pour l'administration par programmation. Chaque
interface utilise les mêmes opérations et les mêmes vérifications de rôles que
la console d'administration.

Pour identifier l'opération associée à un contrôle de la console, ouvrez le
[Developer Panel](/developers/developer-panel) sur cette page.

## Modèle de connexion commun

Les trois interfaces nécessitent une clé API d'organisation. Le Role attribué
détermine les opérations que la clé peut utiliser.

<Mermaid
  title="Trois clients, une seule API, un seul ensemble d'opérations"
  chart={`
flowchart TB
  CLI["Ciele CLI"]
  MCP["Ciele MCP server"]
  HTTP["HTTP client"]
  API["Ciele API v1"]
  OPS["Shared operations"]
  DB[("Organization data")]
  CLI --> API
  MCP --> API
  HTTP --> API
  API --> OPS
  OPS --> DB
`}
/>

Le service hébergé utilise `https://ciele.app` par défaut. Une installation
auto-hébergée utilise sa propre origine publique.

<Callout title="Use the minimum Role">
Create a Viewer key for read operations. Create a higher-role key only when the client must change data or publish an Assistant. A Viewer key is not a read-only agent: it can also curate the Inbox (pin, leave feedback, delete a conversation).
</Callout>

## Domaines disponibles

La [API reference](/api-reference) répertorie toutes les opérations `/api/v1`
disponibles, par domaine.

L'API n'expose pas toutes les fonctions de la console. Par exemple, le
téléchargement d'avatar et la création d'Improvement restent réservés à la
console.
