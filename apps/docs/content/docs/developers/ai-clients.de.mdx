---
title: KI-Clients verbinden
description: Verbinden Sie unterstützte KI-Clients mit dem gehosteten oder lokalen Ciele MCP-Server.
---

Der Ciele MCP-Server verfügt über zwei Transports. Beide registrieren dieselben
Tools.

- Der **hosted endpoint** ist `POST /api/mcp` in Ihrer Bereitstellung. Jeder
  Client, der eine Remote-MCP-URL akzeptiert, kann ihn verwenden.
- Der **local server** ist ein `stdio`-Prozess, den der Client als
  untergeordneten Prozess startet.

Bevorzugen Sie den **hosted endpoint**. Es sind weder ein Checkout noch Node.js
auf dem Client-Rechner erforderlich, und es muss kein Pfad aktuell gehalten
werden.

Diese Seite gibt die am 6. August 2026 geprüfte Client-Dokumentation wieder.
Client-Schnittstellen und Konfigurationsformate können sich ändern.

## Kompatibilität

| Client | Hosted endpoint | Lokal `stdio` |
| --- | :---: | :---: |
| Claude Code | Ja | Ja |
| Codex CLI, Codex App und Codex IDE-Erweiterung | Ja | Ja |
| ChatGPT Desktop-App | Ja | Ja |
| Cursor | Ja | Ja |
| OpenCode | Ja | Ja |
| GitHub Copilot in VS Code | Ja | Ja |
| GitHub Copilot CLI | Ja | Ja |
| ChatGPT web | Ja | Kein lokaler Prozess |
| Pi | Keine integrierte Prozedur | Keine integrierte Prozedur |

## Verbindung zum gehosteten Endpoint herstellen

1. Erstellen Sie einen Viewer-[API key](/developers/api-keys).
2. Geben Sie dem Client die Endpoint-URL für Ihre Bereitstellung.
3. Konfigurieren Sie den `Authorization`-Header als `Bearer <key>`.

```bash
claude mcp add --transport http ciele https://ciele.example.edu/api/mcp \
  --header "Authorization: Bearer ciele_sk_..."
```

Der gehostete Endpoint verfügt über keinen Schalter für den reinen Lesezugriff:
Seine Berechtigungen ergeben sich aus der Role des Schlüssels. Ein
Viewer-Schlüssel ist jedoch kein reiner Read-only-Agent – das Überprüfen von
Konversationen gilt als Curation, sodass er eine Konversation anheften, Feedback
hinterlassen und eine Konversation löschen kann. Verwenden Sie einen lokalen
stdio-Server mit `CIELE_MCP_READ_ONLY=1`, wenn der Agent überhaupt nichts ändern
darf.

## Eine lokale Verbindung vorbereiten

1. Installieren Sie Node.js 22.6 oder höher.
2. Klonen Sie das Ciele-Repository.
3. Erstellen Sie einen Viewer-[API key](/developers/api-keys).
4. Ermitteln Sie den absoluten Pfad zu `packages/mcp/bin/ciele-mcp.mjs`.
5. Legen Sie `CIELE_MCP_READ_ONLY=1` für die erste Verbindung fest.

Ersetzen Sie `<repo>` und den Beispiel-Origin in jeder Konfiguration.

## Claude Code

Führen Sie diesen Befehl aus:

```bash
claude mcp add ciele \
  --env CIELE_API_KEY=ciele_sk_... \
  --env CIELE_BASE_URL=https://ciele.example.edu \
  --env CIELE_MCP_READ_ONLY=1 \
  -- node <repo>/packages/mcp/bin/ciele-mcp.mjs
```

Öffnen Sie `/mcp` in Claude Code. Vergewissern Sie sich, dass der `ciele`-Server
sechzehn Tools anzeigt.

Weitere Informationen zu Client-Optionen und Konfigurationsbereichen finden Sie
im [Claude Code MCP guide](https://docs.anthropic.com/en/docs/claude-code/mcp).

## Codex und ChatGPT Desktop

Führen Sie diesen Befehl für die Codex CLI aus:

```bash
codex mcp add ciele \
  --env CIELE_API_KEY=ciele_sk_... \
  --env CIELE_BASE_URL=https://ciele.example.edu \
  --env CIELE_MCP_READ_ONLY=1 \
  -- node <repo>/packages/mcp/bin/ciele-mcp.mjs
```

Codex CLI, die Codex-App, die Codex-IDE-Erweiterung und ChatGPT Desktop
verwenden dieselbe Codex-MCP-Konfiguration.

Sie können auch `~/.codex/config.toml` bearbeiten:

```toml
[mcp_servers.ciele]
command = "node"
args = ["<repo>/packages/mcp/bin/ciele-mcp.mjs"]
default_tools_approval_mode = "writes"

[mcp_servers.ciele.env]
CIELE_API_KEY = "ciele_sk_..."
CIELE_BASE_URL = "https://ciele.example.edu"
CIELE_MCP_READ_ONLY = "1"
```

Führen Sie `codex mcp list` aus oder öffnen Sie `/mcp`, um die Verbindung zu
überprüfen.

Siehe den [Codex MCP guide](https://learn.chatgpt.com/docs/extend/mcp) für die
aktuellen Client-Einstellungen.

## Cursor

Erstellen Sie `.cursor/mcp.json` in einem Projekt. Sie können auch die globale
Cursor-Konfiguration verwenden.

```json
{
  "mcpServers": {
    "ciele": {
      "command": "node",
      "args": ["<repo>/packages/mcp/bin/ciele-mcp.mjs"],
      "env": {
        "CIELE_API_KEY": "ciele_sk_...",
        "CIELE_BASE_URL": "https://ciele.example.edu",
        "CIELE_MCP_READ_ONLY": "1"
      }
    }
  }
}
```

Öffnen Sie **Settings > MCP**. Aktivieren Sie `ciele` und überprüfen Sie jeden
angeforderten Tool-Aufruf.

Siehe den
[Cursor MCP guide](https://docs.cursor.com/context/model-context-protocol) für
Informationen zur globalen Konfiguration und zur Sicherheit des Clients.

## OpenCode

Fügen Sie diesen Server zu `opencode.json` hinzu:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "ciele": {
        "type": "local",
        "command": ["node", "<repo>/packages/mcp/bin/ciele-mcp.mjs"],
        "environment": {
          "CIELE_API_KEY": "{env:CIELE_API_KEY}",
          "CIELE_BASE_URL": "https://ciele.example.edu",
          "CIELE_MCP_READ_ONLY": "1"
        }
      }
    }
  }
}
```

Führen Sie `opencode2 mcp list` aus, um die Verbindung zu prüfen.

Siehe den [OpenCode MCP guide](https://opencode.ai/v2/docs/mcp-servers) für das
aktuelle Schema der Version 2.

## GitHub Copilot in VS Code

`.vscode/mcp.json` erstellen:

```json
{
  "inputs": [
    {
      "id": "ciele-key",
      "type": "promptString",
      "password": true,
      "description": "Ciele API key"
    }
  ],
  "servers": {
    "ciele": {
      "type": "stdio",
      "command": "node",
      "args": ["<repo>/packages/mcp/bin/ciele-mcp.mjs"],
      "env": {
        "CIELE_API_KEY": "${input:ciele-key}",
        "CIELE_BASE_URL": "https://ciele.example.edu",
        "CIELE_MCP_READ_ONLY": "1"
      }
    }
  }
}
```

Führen Sie **MCP: List Servers** über die Command Palette aus. Starten Sie
`ciele` und prüfen Sie die Ausgabe, wenn eine Verbindung fehlschlägt.

Informationen zu den Speicherorten der Konfiguration und den Einstellungen für
Vertrauenssteuerungen finden Sie im
[VS Code MCP guide](https://code.visualstudio.com/docs/agent-customization/mcp-servers).

## GitHub Copilot CLI

Führen Sie den interaktiven Befehl `/mcp add` aus. Wählen Sie einen lokalen
`stdio`-Server aus und geben Sie den Ciele-Befehl ein.

Sie können auch mit diesem Befehl beginnen:

```bash
copilot mcp add ciele -- node <repo>/packages/mcp/bin/ciele-mcp.mjs
```

Fügen Sie die drei Ciele-Umgebungsvariablen über die Copilot-MCP-Konfiguration
hinzu. Fügen Sie den API-Schlüssel nicht in das Versionskontrollsystem ein.

Informationen zum aktuellen Konfigurationsformat finden Sie im
[GitHub Copilot CLI MCP guide](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-mcp-servers).

## Kopierbare Prompts

Beginnen Sie jede neue Verbindung mit dieser schreibgeschützten Prüfung:

```text
Call ciele_identity. Show the deployment version, available domains,
Organization ID, and Role. Do not change data.
```

Verwenden Sie diesen Prompt, um Assistants zu überprüfen:

```text
List all Ciele Assistants. For each Assistant, list its enabled Flows.
Identify duplicate or unclear Flow names. Do not change data.
```

Verwenden Sie diesen Prompt, um die Knowledge Ingestion zu überprüfen:

```text
List the Sources linked to Assistant <assistant-id>.
List each Source and its ingestion status.
Report Sources that are not ready. Do not retry or delete a Source.
```

Verwenden Sie diesen Prompt, nachdem Sie den Schreibzugriff aktiviert haben:

```text
Create one FAQ for Assistant <assistant-id>.
Question: "When does enrollment close?"
Answer: "Enrollment closes on <date>."
Show the proposed tool input and ask for approval before the call.
```

Verwenden Sie diesen Prompt vor der Veröffentlichung:

```text
Read the publication status for Assistant <assistant-id>.
Summarize the current live version. Do not publish or unpublish anything.
```

<Callout type="warn" title="Review write operations">
Read the proposed tool input before you approve it. API Roles and MCP read-only mode are independent controls.
</Callout>

## Clients ohne lokalen Prozess

ChatGPT Web kann keinen lokalen `stdio` Server starten. Richten Sie es
stattdessen auf den gehosteten Endpoint. Die Bereitstellung muss über das
öffentliche Internet erreichbar sein, was bei einem lokalen Ciele Desktop-Stack
nicht der Fall ist.

Pi enthält kein integriertes MCP-Verbindungsverfahren. Pi-Erweiterungen können
MCP-Unterstützung hinzufügen, aber Ciele liefert eine solche Erweiterung weder
aus noch testet sie. Verwenden Sie `ciele ... --json` über einen genehmigten
Shell-Workflow oder rufen Sie die [HTTP API](/developers/api) direkt auf.
