title: Server MCP di Ciele
description: Concedi a un client MCP l'accesso controllato alle operazioni di amministrazione di Ciele.

Il server Ciele Model Context Protocol (MCP) espone le operazioni di
amministrazione a un agente IA. Dispone di due transport, ed entrambi registrano
gli stessi strumenti.

- L'**hosted endpoint** è `POST /api/mcp` sulla tua distribuzione. Usalo per un
  client che si connette tramite HTTP.
- Il **local server** è un processo `stdio` che avvii da un checkout del
  repository.

Ogni chiamata a uno strumento raggiunge l'Organization tramite `/api/v1`, quindi
un'operazione ha un unico percorso di esecuzione, indipendentemente dal
trasporto che l'ha richiesta.

## Endpoint ospitato

Ogni deployment di Ciele espone l'endpoint dal proprio origin. Ciò include il
servizio ospitato, un self-host Docker e lo stack locale di Ciele Desktop.
L'endpoint non richiede alcuna configurazione.

```text
https://ciele.example.edu/api/mcp
```

Esegui l'autenticazione con una [Organization API key](/developers/api-keys)
nell'header `Authorization`:

```text
Authorization: Bearer ciele_sk_...
```

Una chiave sconosciuta o assente viene rifiutata con `401` prima che venga
elencato qualsiasi strumento.

<Callout title="The key Role is the permission boundary">
The hosted endpoint has no read-only switch. Its permissions are the Role of the key: the operations layer refuses a mutation the Role does not cover with `403`. A Viewer key is not a read-only agent, though. Reviewing conversations counts as curation, so a Viewer key can pin a conversation, leave feedback, and delete a conversation. Use `CIELE_MCP_READ_ONLY=1` on a stdio server when you need an agent that cannot write at all.
</Callout>

## Revisioni del protocollo

Il server supporta la revisione `2026-07-28` e le revisioni 2025. Determina la
revisione fin dallo scambio iniziale, perciò un client che non è passato a
`2026-07-28` continua a funzionare.

La revisione `2026-07-28` ha rimosso le sessioni di protocollo. Ogni richiesta è
indipendente, pertanto l'endpoint ospitato non necessita di sticky routing né di
un session store.

## Server `stdio` locale

### Requisiti

- Utilizza Node.js 22.6 o versioni successive.
- Clona il repository di Ciele.
- Crea una [chiave API dell'organizzazione](/developers/api-keys).
- Utilizza un client MCP in grado di avviare un server `stdio` locale.

Avvia questo programma dal repository:

```text
node <repo>/packages/mcp/bin/ciele-mcp.mjs
```

### Variabili di ambiente

| Variable | Requirement | Purpose |
| --- | --- | --- |
| `CIELE_API_KEY` | Obbligatoria | Autentica l'organizzazione. |
| `CIELE_BASE_URL` | Optional | Seleziona un'origine self-hosted. |
| `CIELE_MCP_READ_ONLY` | Optional | Rifiuta le azioni di mutazione quando il valore è `1`. |
| `CIELE_MCP_MODERN_ONLY` | Optional | Rifiuta i client della revisione 2025 quando il valore è `1`. |

Il controllo di sola lettura avviene all'interno del processo MCP. Una mutazione
rifiutata non effettua una richiesta API.

<Callout type="warn" title="These variables apply to the local server only">
A Ciele web container ignores `CIELE_MCP_READ_ONLY` and `CIELE_MCP_MODERN_ONLY`. Do not set them on a deployment and expect the hosted endpoint to obey.
</Callout>

<Callout title="Recommended first connection">
Use a viewer key and set `CIELE_MCP_READ_ONLY=1`. Remove one restriction only when the agent must change Ciele data.
</Callout>

## Strumenti disponibili

| Tool | Operazioni correnti |
| --- | --- |
| `ciele_identity` | Leggi le informazioni su Deployment, Organization e Role. |
| `manage_assistants` | Elenca, leggi, crea, aggiorna, duplica o elimina gli Assistants. |
| `manage_flows` | Leggi il catalogo dei Flow, controlla un Flow senza salvarlo, leggi le esecuzioni di un HTTP Flow, quindi elenca, leggi, crea, aggiorna, riordina o elimina i Flow. |
| `manage_knowledge` | Gestisci Collections, Sources e FAQ. |
| `publish_assistant` | Leggi lo stato, pubblica, annulla la pubblicazione o ripristina una pubblicazione. |
| `read_inbox` | Elenca, leggi, esporta, appunta, annota, valuta o elimina le Conversations. Elenca, leggi e decidi le richieste di revisione umana. |
| `manage_improvements` | Elenca, leggi o aggiorna gli Improvements. |
| `manage_entities` | Gestisci le Organization Entities e i Records tipizzati. |
| `manage_memories` | Verifica le impostazioni ed esegui la cancellazione della memoria con ambito definito. |
| `manage_sso` | Gestisci le identity claim e la connessione SSO dell'organizzazione. |
| `manage_help_desks` | Gestisci Help Desk, canali, ordinamento e ServiceNow. |
| `manage_teammates` | Gestisci gli AI Teammate, i loro grant, le loro Routine e la loro memoria. `provision` esegue la configurazione completa con una sola azione. |
| `manage_projects` | Gestisci i progetti e il documento di memoria di ciascun progetto. |
| `manage_channels` | Leggi e modella i canali dei teammate in cui sei presente. |
| `manage_configuration` | Gestisci Skills, la selezione di Assistant Skills, Goals e Alerts. |
| `manage_organization` | Gestisci le impostazioni dell'organizzazione, i Members, gli Invites e le API keys. Consulta i contatori di utilizzo e gli spender del piano. |
| `manage_integrations` | Gestisci le integrazioni API dell'Assistente e i provider di modelli. |

Il server registra diciassette tool: un identity tool e sedici domain tool. Ogni
strumento di dominio utilizza un campo `action` per le proprie operazioni.

La modalità di sola lettura classifica ogni azione. Consente le azioni list,
read, status, query ed export, mentre rifiuta le mutazioni.

Consulta [AI clients](/developers/ai-clients) per la configurazione di ciascun
client supportato.

## Verifica la connessione

Chiedi al client di chiamare `ciele_identity`. Conferma l'Organization ID, il
Role, la versione dell'API e l'elenco dei domini previsti.

La suite di test del repository avvia anche il processo `stdio` reale. Verifica
l'inizializzazione, il rilevamento degli strumenti e una chiamata API
autenticata.
