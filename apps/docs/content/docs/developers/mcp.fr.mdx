---
title: Serveur MCP Ciele
description: Accorder à un client MCP un accès contrôlé aux opérations d'administration de Ciele.
---

Le serveur Ciele Model Context Protocol (MCP) expose les opérations
d'administration à un agent d'IA. Il dispose de deux transports, et les deux
enregistrent les mêmes outils.

- Le **hosted endpoint** est `POST /api/mcp` sur votre déploiement. Utilisez-le
  pour un client qui se connecte via HTTP.
- Le **local server** est un processus `stdio` que vous démarrez à partir d'un
  clonage de dépôt.

Chaque appel d'outil atteint l'Organisation via `/api/v1`, de sorte qu'une
opération suit un seul chemin d'exécution, quel que soit le transport qui l'a
demandée.

## Point de terminaison hébergé

Chaque déploiement Ciele expose l'endpoint depuis sa propre origine. Cela inclut
le service hébergé, un auto-hébergement Docker et la pile locale de Ciele
Desktop. Le point de terminaison ne nécessite aucune configuration.

```text
https://ciele.example.edu/api/mcp
```

Authentifiez-vous à l'aide d'une
[clé API de l'organisation](/developers/api-keys) dans l'en-tête `Authorization`
:

```text
Authorization: Bearer ciele_sk_...
```

Une clé inconnue ou absente est refusée avec `401` avant qu'aucun outil ne soit
répertorié.

<Callout title="The key Role is the permission boundary">
The hosted endpoint has no read-only switch. Its permissions are the Role of the key: the operations layer refuses a mutation the Role does not cover with `403`. A Viewer key is not a read-only agent, though. Reviewing conversations counts as curation, so a Viewer key can pin a conversation, leave feedback, and delete a conversation. Use `CIELE_MCP_READ_ONLY=1` on a stdio server when you need an agent that cannot write at all.
</Callout>

## Révisions du protocole

Le serveur prend en charge la révision `2026-07-28` et les révisions 2025. Il
détermine la révision dès l'échange d'ouverture, de sorte qu'un client qui n'est
pas passé à `2026-07-28` continue de fonctionner.

La révision `2026-07-28` a supprimé les sessions de protocole. Chaque requête
est autonome ; par conséquent, l'endpoint hébergé n'a pas besoin de routage
persistant ni de stockage de session.

## Serveur `stdio` local

### Configuration requise

- Utilisez Node.js 22.6 ou une version ultérieure.
- Clonez le dépôt Ciele.
- Créez une [clé API d'organisation](/developers/api-keys).
- Utilisez un client MCP capable de démarrer un serveur local `stdio`.

Démarrez ce programme à partir du dépôt :

```text
node <repo>/packages/mcp/bin/ciele-mcp.mjs
```

### Variables d'environnement

| Variable | Exigence | Objectif |
| --- | --- | --- |
| `CIELE_API_KEY` | Obligatoire | Authentifie l'organisation. |
| `CIELE_BASE_URL` | Facultatif | Sélectionne une origine auto-hébergée. |
| `CIELE_MCP_READ_ONLY` | Facultatif | Refuse les actions de mutation lorsque la valeur est `1`. |
| `CIELE_MCP_MODERN_ONLY` | Optional | Refuse les clients de la révision 2025 lorsque la valeur est `1`. |

La vérification en lecture seule a lieu au sein du processus MCP. Une mutation
refusée n'effectue pas de requête API.

<Callout type="warn" title="These variables apply to the local server only">
A Ciele web container ignores `CIELE_MCP_READ_ONLY` and `CIELE_MCP_MODERN_ONLY`. Do not set them on a deployment and expect the hosted endpoint to obey.
</Callout>

<Callout title="Recommended first connection">
Use a viewer key and set `CIELE_MCP_READ_ONLY=1`. Remove one restriction only when the agent must change Ciele data.
</Callout>

Le serveur enregistre dix-sept outils : un outil d'identité et seize outils de
domaine. Chaque outil de domaine utilise un champ `action` pour ses opérations.

Le mode lecture seule classe chaque action. Il autorise les actions list, read,
status, query, search et export, tout en refusant les mutations.

## Rechercher dans la base de connaissances

L'action `search` de `manage_knowledge` identifie les passages qui correspondent
à une question. Chaque résultat indique le texte du passage, son Document title,
son Source name et son URL lorsqu'il en existe une. Ciele ne génère pas de
réponse. Votre client IA rédige la réponse et cite les Sources.

```json
{ "action": "search", "query": "How do I connect Salesforce?", "assistantId": "<assistant-id>" }
```

Avec `assistantId`, la recherche utilise uniquement les Sources liées à cet
Assistant. Sans cela, la recherche utilise l'ensemble de la Library de
l'Organisation. Une clé viewer permet d'effectuer des recherches, et le mode
lecture seule l'autorise. Une recherche ne crée pas de Conversation ; elle
n'apparaît donc ni dans l'Inbox ni dans les Insights. Chaque clé API peut
effectuer 60 recherches en une minute.

## Demander à un Assistant

L'action `ask` de `manage_assistants` envoie une question à un Assistant et
renvoie sa réponse accompagnée des Sources qu'il a citées. Utilisez-la lorsque
le client doit afficher la réponse de Ciele, et non sa propre réponse.

```json
{ "action": "ask", "id": "<assistant-id>", "question": "How do I connect Salesforce?" }
```

L'Assistant répond comme le fait son widget publié, avec ses Flows et sa
recherche dans la base de connaissances. Si l'Assistant n'est pas publié,
l'action échoue. Envoyez le `conversationId` d'une réponse avec la question
suivante pour poursuivre la même Conversation. Seule la clé API qui a initié une
Conversation peut la poursuivre. Avec un ID différent, la question démarre une
nouvelle Conversation.

Chaque question crée une Conversation. Insights ne le prend pas en compte. La
boîte de réception l'affiche avec l'étiquette **API key** lorsque vous réglez le
filtre **Staff conversations** sur **Include staff** ou **Staff only**. La
question utilise un tour de modèle sur les Provider Connections de
l'Organisation. Pour cette raison, le mode lecture seule refuse `ask`. Chaque
clé API peut poser 20 questions en une minute. Une réponse peut prendre un
certain temps, car l'Assistant peut effectuer plusieurs recherches.

Consultez [AI clients](/developers/ai-clients) pour la configuration de chaque
client pris en charge.

## Vérifier la connexion

Demandez au client d'appeler `ciele_identity`. Confirmez l'identifiant
d'organisation, le rôle, la version de l'API et la liste des domaines attendus.

La suite de tests du dépôt lance également le processus `stdio` réel. Elle
vérifie l'initialisation, la découverte des outils et un appel d'API
authentifié.
