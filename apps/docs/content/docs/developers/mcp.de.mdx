Der Ciele Model Context Protocol (MCP)-Server stellt die Verwaltungsvorgänge
einem KI-Agenten zur Verfügung. Er verfügt über zwei Transportschichten, und
beide registrieren dieselben Tools.

- Der **hosted endpoint** ist `POST /api/mcp` in Ihrer Bereitstellung. Verwenden
  Sie ihn für einen Client, der sich über HTTP verbindet.
- Der **local server** ist ein `stdio`-Prozess, den Sie nach dem Auschecken
  eines Repositorys starten.

Jeder Tool-Aufruf erreicht die Organisation über `/api/v1`, sodass eine
Operation unabhängig davon, welcher Transport sie angefordert hat, nur einen
Ausführungspfad hat.

## Gehosteter Endpunkt

Jede Ciele-Bereitstellung stellt den Endpoint an ihrem eigenen Ursprung bereit.
Dazu gehören der gehostete Service, ein Docker-Self-Host und der lokale Stack
von Ciele Desktop. Der Endpoint erfordert keine Konfiguration.

```text
https://ciele.example.edu/api/mcp
```

Authentifizieren Sie sich mit einem [Organization API key](/developers/api-keys)
im `Authorization`-Header:

```text
Authorization: Bearer ciele_sk_...
```

Ein unbekannter oder fehlender Schlüssel wird mit `401` abgelehnt, bevor ein
Tool aufgelistet wird.

<Callout title="The key Role is the permission boundary">
The hosted endpoint has no read-only switch. Its permissions are the Role of the key: the operations layer refuses a mutation the Role does not cover with `403`. A Viewer key is not a read-only agent, though. Reviewing conversations counts as curation, so a Viewer key can pin a conversation, leave feedback, and delete a conversation. Use `CIELE_MCP_READ_ONLY=1` on a stdio server when you need an agent that cannot write at all.
</Callout>

## Protokollrevisionen

Der Server unterstützt die `2026-07-28`-Revision sowie die 2025-Revisionen. Es
ermittelt die Revision anhand des ersten Austauschs, sodass ein Client, der noch
nicht auf `2026-07-28` umgestiegen ist, weiterhin funktioniert.

Mit der Revision `2026-07-28` wurden Protokoll-Sessions entfernt. Jede Anfrage
ist in sich abgeschlossen, sodass der gehostete Endpoint weder Sticky Routing
noch einen Session Store benötigt.

## Lokaler `stdio`-Server

### Voraussetzungen

- Verwenden Sie Node.js 22.6 oder höher.
- Klonen Sie das Ciele-Repository.
- Erstellen Sie einen [Organization API key](/developers/api-keys).
- Verwenden Sie einen MCP-Client, der einen lokalen `stdio`-Server starten kann.

Starten Sie dieses Programm aus dem Repository:

```text
node <repo>/packages/mcp/bin/ciele-mcp.mjs
```

### Umgebungsvariablen

| Variable | Anforderung | Zweck |
| --- | --- | --- |
| `CIELE_API_KEY` | Erforderlich | Authentifiziert die Organisation. |
| `CIELE_BASE_URL` | Optional | Wählt einen selbst gehosteten Ursprung aus. |
| `CIELE_MCP_READ_ONLY` | Optional | Lehnt Mutationsaktionen ab, wenn der Wert `1` ist. |
| `CIELE_MCP_MODERN_ONLY` | Optional | Lehnt Clients der Revision 2025 ab, wenn der Wert `1` ist. |

Die Read-only-Prüfung findet innerhalb des MCP-Prozesses statt. Bei einer
abgelehnten Mutation wird keine API-Anfrage gestellt.

<Callout type="warn" title="These variables apply to the local server only">
A Ciele web container ignores `CIELE_MCP_READ_ONLY` and `CIELE_MCP_MODERN_ONLY`. Do not set them on a deployment and expect the hosted endpoint to obey.
</Callout>

<Callout title="Recommended first connection">
Use a viewer key and set `CIELE_MCP_READ_ONLY=1`. Remove one restriction only when the agent must change Ciele data.
</Callout>

| Tool | Aktuelle Operationen |
| --- | --- |
| `ciele_identity` | Informationen zu Deployment, Organization und Role lesen. |
| `manage_assistants` | Stellen Sie einem Assistenten eine Frage und führen Sie anschließend folgende Aktionen durch: Assistants auflisten, lesen, erstellen, aktualisieren, duplizieren oder löschen. |
| `manage_flows` | Lesen Sie den Flow-Katalog, prüfen Sie einen Flow, ohne ihn zu speichern, lesen Sie die Runs eines HTTP-Flows und führen Sie anschließend folgende Aktionen mit Flows durch: auflisten, lesen, erstellen, aktualisieren, neu anordnen oder löschen. |
| `manage_knowledge` | Durchsuchen Sie das Wissen und verwalten Sie anschließend Collections, Sources und FAQs. |
| `publish_assistant` | Status lesen, eine Veröffentlichung veröffentlichen, die Veröffentlichung aufheben oder eine Veröffentlichung wiederherstellen. |
| `read_inbox` | Conversations auflisten, lesen, exportieren, anheften, kommentieren, bewerten oder löschen. Human Review Requests auflisten, lesen und entscheiden. |
| `manage_improvements` | Improvements auflisten, lesen oder aktualisieren. |
| `manage_memories` | Einstellungen prüfen und eine bereichsbezogene Löschung des Speichers durchführen. |
| `manage_sso` | Verwalten Sie Identity Claims und die SSO-Verbindung der Organisation. |
| `manage_help_desks` | Verwalten Sie Help Desks, Channels, Ordering und ServiceNow. |
| `manage_teammates` | Verwalten Sie AI Teammates, ihre Berechtigungen, ihre Routines und ihren Speicher. `provision` führt die vollständige Einrichtung in einem einzigen Schritt durch. |
| `manage_projects` | Verwalten Sie Projects und das Memory-Dokument jedes Projekts. |
| `manage_channels` | Lesen und gestalten Sie die Teammate-Kanäle, in denen Sie sich befinden. |
| `manage_configuration` | Verwalten Sie Skills, die Auswahl der Assistant Skills, Goals und Alerts. |
| `manage_organization` | Verwalten Sie die Einstellungen der Organisation, Members, Invites und API keys. Lesen Sie die Nutzungsmessungen und die Ausgaben des Plans. |
| `manage_integrations` | Verwalten Sie Assistant-API-Integrationen und Modellanbieter. |

Der Server registriert sechzehn Tools: ein Identity-Tool und fünfzehn
Domain-Tools. Jedes Domain-Tool verwendet ein `action`-Feld für seine
Operationen.

Der Read-only-Modus klassifiziert jede Aktion. Es erlaubt die Aktionen list,
read, status, query, search und export, während es Mutationsvorgänge ablehnt.

## Die Wissensdatenbank durchsuchen

Die Aktion `search` von `manage_knowledge` findet die Passagen, die zu einer
Frage passen. Jedes Ergebnis enthält den Text der Passage, den Titel des
Dokuments, den Namen der Quelle und – falls vorhanden – die URL. Ciele generiert
keine Antwort. Ihr KI-Client verfasst die Antwort und nennt die Quellen.

```json
{ "action": "search", "query": "How do I connect Salesforce?", "assistantId": "<assistant-id>" }
```

Mit `assistantId` verwendet die Suche nur die Quellen, die mit diesem Assistant
verknüpft sind. Ohne sie verwendet die Suche die gesamte Library der
Organisation. Ein Viewer-Schlüssel kann suchen, und der Read-only-Modus erlaubt
dies. Eine Suche erstellt keine Conversation, daher wird sie weder im Inbox noch
in den Insights angezeigt. Jeder API-Schlüssel kann 60 Suchen pro Minute
durchführen.

## Einen Assistenten fragen

Die Aktion `ask` von `manage_assistants` sendet eine Frage an einen Assistenten
und gibt dessen Antwort zusammen mit den von ihm zitierten Quellen zurück.
Verwenden Sie sie, wenn der Client die Antwort von Ciele anzeigen muss, nicht
seine eigene Antwort.

```json
{ "action": "ask", "id": "<assistant-id>", "question": "How do I connect Salesforce?" }
```

Der Assistant antwortet wie sein veröffentlichtes Widget, mit seinen Flows und
seiner Wissenssuche. Wenn der Assistant nicht veröffentlicht ist, schlägt die
Aktion fehl. Senden Sie die `conversationId` einer Antwort zusammen mit der
nächsten Frage, um dieselbe Conversation fortzusetzen. Nur der API-Schlüssel,
mit dem eine Conversation gestartet wurde, kann sie fortsetzen. Mit einer
anderen ID startet die Frage eine neue Conversation.

Jede Frage erzeugt eine Conversation. Insights zählt es nicht. Die Inbox zeigt
es mit dem Label **API key** an, wenn Sie den Filter **Staff conversations** auf
**Include staff** oder **Staff only** setzen. Die Frage verwendet einen
Model-Turn in den Provider Connections der Organisation. Aus diesem Grund lehnt
der schreibgeschützte Modus `ask` ab. Jeder API-Schlüssel kann innerhalb einer
Minute 20 Fragen stellen. Eine Antwort kann einige Zeit in Anspruch nehmen, da
der Assistant möglicherweise mehr als einmal suchen muss.

Siehe [AI clients](/developers/ai-clients) für die Konfiguration jedes
unterstützten Clients.

## Verbindung prüfen

Bitten Sie den Client, `ciele_identity` aufzurufen. Bestätigen Sie die erwartete
Organization ID, Role, API-Version und Domain-Liste.

Die Repository-Testsuite startet ebenfalls den tatsächlichen `stdio`-Prozess.
Sie überprüft die Initialisierung, die Tool-Erkennung und einen
authentifizierten API-Aufruf.
