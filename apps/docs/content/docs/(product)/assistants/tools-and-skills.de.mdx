Öffnen Sie einen Assistant und wählen Sie **Tools & Skills**. In diesem
Abschnitt werden die Laufzeitfunktionen und wiederverwendbaren Anweisungen
gesteuert.

## Integrierte Tools

| Tool | Default | Aktuelles Verhalten |
| --- | :---: | --- |
| Search knowledge | On | Durchsucht das verbundene Knowledge und gibt zitierte Antworten zurück. |
| Session memory | On | Verwendet Informationen aus der aktuellen Konversationssitzung. |
| Fetch URL | Off | Liest eine URL, wenn die Runtime das Tool auswählt. |
| Interactive tables | Off | Zeigt Fakten als einfache Tabelle, als CRM-Datensraster oder als Aufgabentabelle mit Statusfiltern an. |

Search Knowledge ist stets verfügbar. Sie können die anderen integrierten Tools
aktivieren oder deaktivieren.

**Interactive tables** ordnet Fakten an, die der Assistant in dieser Antwort
gefunden hat. Die Runtime wählt die Tabelle basierend auf Ihrer Anfrage und den
verfügbaren Daten aus.

- Eine einfache Tabelle vergleicht Fakten und kann Folgefragen zu einzelnen
  Zeilen enthalten.
- Ein CRM-Datensraster zeigt Unternehmen, Kategorien, die letzte Interaktion,
  den Beziehungsstatus und Website-Links an. Wählen Sie Zeilen aus, sortieren
  Sie, ändern Sie die Größe oder heften Sie Spalten an.
- Eine Aufgabentabelle zeigt Daten, Status und Verantwortliche an. Wählen Sie
  **All**, **To do**, **In Progress** oder **Completed** aus, um die Zeilen zu
  filtern.

Die Filteranzahlen basieren auf den angezeigten Daten. Fehlende Daten bleiben
leer. Tabelleneinstellungen wirken sich auf die aktuelle Ansicht aus und ändern
keine CRM-Datensätze.

Verwenden Sie **New property** oder **Add calculation** im CRM-Grid, um eine
Property-Anfrage vorzubereiten. Überprüfen Sie den Prompt und wählen Sie
anschließend **Go calculate** aus. Dadurch wird eine normale Chat-Anfrage
gesendet. Das aktuelle Harness, die verbundenen Quellen und die Berechtigungen
gelten weiterhin. Die Benutzeroberfläche simuliert keine generierten Werte.

Die gleichen Tabellen werden in Preview, im veröffentlichten Widget und im
Inbox-Transkript angezeigt. Veröffentlichen Sie den Assistant, nachdem Sie
dieses Tool aktiviert haben. Die Inbox unterstützt Anzeigen, Auswählen, Filtern
und das Spaltenlayout. Es sendet keine Property-Anfragen.

Der Assistant kann einer Zeile eine Folgefrage hinzufügen. Der Visitor wählt die
Zeile aus, um diese Frage zu stellen. Das Inbox-Transkript zeigt diese Zeilen
an, aber ein Member kann sie nicht auswählen.

## Study Mode aktivieren

**Study Mode** ist standardmäßig deaktiviert. Aktivieren Sie es, damit Besucher
das Wissen des Assistenten mit interaktiven Übungen üben können.

1. Öffnen Sie **Tools & Skills** und aktivieren Sie **Study Mode**.
2. Aktivieren Sie mindestens ein Frageformat.
3. Fügen Sie **Custom instructions** hinzu, um den Teaching Style festzulegen.
4. Testen Sie eine Übung in der Vorschau.
5. Veröffentlichen Sie den Assistant, um das Widget zu aktualisieren.

Der Chat-Editor zeigt eine Schaltfläche **Study exercises** an. Wählen Sie ein
Format aus, fügen Sie ein Thema hinzu und senden Sie dann die Anfrage.

Wenn aktiviert, wird **Study Mode** auch in **Flows** angezeigt. Die
Schaltfläche Settings öffnet diesen Abschnitt. Deaktivieren Sie den Study Mode
in **Tools & Skills**. Der Flow hat keinen separaten Schalter. Anfragen aus dem
Menü „Study exercises“ gehen direkt an diesen Flow. In Thinking wird ein Symbol
mit einer Doktorhut-Kappe angezeigt.

Für Übungen ist relevantes Material in der Knowledge-Basis des Assistenten
erforderlich. Wenn kein Material gefunden wird, fragt der Assistant nach einem
unterstützten Thema oder nach Lernmaterial.

| Format | Wie der Visitor antwortet |
| --- | --- |
| Multiple Choice | Wählen Sie eine Option aus. Es ist keine Freitextantwort verfügbar. |
| Drag the words | Ziehen Sie ein Wort per Drag-and-drop oder wählen Sie es aus, um pro Frage eine Lücke zu füllen. |
| True / False | Wählen Sie eine von zwei Optionen aus. |
| Flashcards | Geben Sie das fehlende Wort oder eine kurze Formulierung ein. |

**Choose for me** wählt ein aktiviertes Format aus. Jede Übung enthält höchstens
fünf verschiedene Fragen, die auf dem abgerufenen Knowledge basieren.

Wählen Sie **Check** aus, um eine Antwort zu speichern. Ciele zeigt an, ob die
Antwort richtig ist, gibt die richtige Antwort an und liefert eine Erklärung.
Eine einmal übermittelte Antwort kann nicht mehr geändert werden. Flashcards
akzeptieren die bei der Erstellung der Übung definierten Schreibvarianten.

Die Inbox zeigt die Fragen, die eingereichten Antworten, die richtigen Antworten
und die Punktzahl an. Unvollendete Übungen zeigen an, wie viele Fragen noch
unbeantwortet sind. Die Übungen werden innerhalb des Chats ausgeführt. Sie
benötigen keinen externen H5P-Player.

## Eine API-Integration konfigurieren

Ein Assistant kann eine registrierte API-Integration verwenden. Die Integration
enthält eine Basis-URL, geschützte Anmeldeinformationen und beschriebene
Endpunkte.

Definieren Sie für jeden Endpoint die Methode, den Pfad, den Zweck, die
Parameter und das Response-Format. Die Runtime überprüft jeden angeforderten
Pfad anhand dieses Katalogs.

Der Agent kann die Details des Endpunkts prüfen, bevor er eine Anfrage sendet.
Große Antworten bleiben über windowed reads verfügbar.

<Callout title="Control the endpoint catalogue">
Add only the endpoints that the Assistant must use. The runtime cannot call an unregistered path through this integration.
</Callout>

### Doppelte Schreibvorgänge verhindern

Eine Anfrage kann nach einem Timeout oder einem Fehler erneut gesendet werden.
Wenn der Endpoint Daten schreibt, kann die zweite Anfrage einen zweiten
Datensatz anlegen.

Um dies zu verhindern, weisen Sie dem Endpoint einen Idempotenzschlüssel zu.
Geben Sie im Formular des Endpunkts an, wo Ihre API den Schlüssel liest:

- `header:Idempotency-Key` sendet den Schlüssel in einem Request-Header.
- `body:request_id` sendet den Schlüssel im JSON-Body.

Verwenden Sie den Namen, den Ihre API liest. Ciele errät diesen Namen nicht.
Verschiedene APIs lesen unterschiedliche Namen aus.

Ciele erstellt für jeden Aufruf einen eigenen Schlüssel. Bei einem erneuten
Versuch desselben Aufrufs wird derselbe Schlüssel gesendet. Ein anderer Aufruf
sendet einen anderen Schlüssel. Ihre API kann dann die beiden Anfragen als einen
einzigen Schreibvorgang betrachten.

Ihre API muss ebenfalls ihren Beitrag leisten. Sie muss den Schlüssel speichern
und das erste Ergebnis zurückgeben, wenn sie den Schlüssel erneut sieht.

<Callout title="An endpoint with no key is not protected">
If you give no key, a retry of the call can write two times. A `GET` endpoint does not need a key, because a read does not change data.
</Callout>

## Eine Organisations-Skill zuordnen

Eine Skill ist eine wiederverwendbare Anweisungsvorlage. Eine Organisation kann
dieselbe Skill mehreren Assistenten zuordnen.

1. Öffnen Sie **Tools & Skills**.
2. Suchen Sie die gewünschte Organization Skill.
3. Fügen Sie die Skill dem Assistant hinzu.
4. Testen Sie das Ergebnis in Preview.
5. Veröffentlichen Sie den Assistant, wenn das Ergebnis korrekt ist.

Skill-Änderungen sind in Preview sofort verfügbar. Das veröffentlichte Widget
verwendet den letzten Publication-Snapshot.

### Ermöglichen Sie es Nutzern, eine Skill aus dem Chat-Fenster heraus zu starten

Eine Skill kann ein **Opening line** haben. Schreiben Sie es aus der Perspektive
der Person, die die Frage stellt, nicht aus der des Assistenten.

Das Chat-Fenster zeigt ein **/**-Menü mit jeder Skill, die eine Eröffnungszeile
hat. Wenn der Benutzer eine Skill auswählt, schreibt das Chat-Fenster die
Opening Line in das Nachrichtenfeld. Sie können den Text bearbeiten, bevor Sie
ihn senden.

Wenn die Opening Line leer ist, wird die Skill nicht im **/**-Menü angezeigt.
Der Skill-Prompt gilt weiterhin für jede Antwort.

Veröffentlichen Sie den Assistant, nachdem Sie eine Eröffnungszeile verfasst
haben. Das Widget verwendet den letzten Snapshot der Publication.

## Attachments und Knowledge sind nicht dasselbe

Sowohl ein Anhang als auch eine Knowledge Source werden zu Text, und Ciele liest
beide mit demselben Extractor. Was danach geschieht, ist anders.

Eine Knowledge Source ist permanent. Ciele speichert den Text, indiziert ihn,
und der Assistant kann ihn in jeder späteren Konversation zitieren.

Ein Anhang gehört zu seiner Konversation. Ciele liest es einmal, verwirft die
Bytes und fügt es niemals zur Library hinzu. Keine andere Konversation hat
Zugriff darauf.

Um eine Datei dauerhaft zu speichern, fügen Sie sie stattdessen in **Library**
hinzu.

## Testen Sie die Konfiguration

Stellen Sie eine Frage, die jedes aktivierte Tool erfordert. Überprüfen Sie das
Thinking-Panel und die Sources, bevor Sie veröffentlichen.

Testen Sie bei strukturierten Daten eine exakte Attributsuche sowie eine
Textsuche. Testen Sie den auf Benutzer*innen-Ebene geltenden Zugriff mit zwei
verschiedenen angemeldeten Konten.
