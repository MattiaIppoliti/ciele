---
title: Actions du flux
description: Sélectionnez les actions de réponse que l'environnement d'exécution actuel peut exécuter.
---

Les actions du flux de messages s'exécutent dans l'ordre. Les actions non
génératives utilisent le contenu configuré sans réécriture par le modèle.

## Actions disponibles

| Action | Utilisation du modèle | Comportement actuel |
| --- | :---: | --- |
| Message | No | Émet le texte configuré tel quel. |
| Button | Non | Ajoute un bouton de lien ou un bouton qui envoie du texte dans le chat. |
| Search knowledge | Oui | Exécute la boucle de l'agent Knowledge et renvoie des citations. |
| Follow-ups | Facultatif | Utilise les questions configurées ou génère des questions suggérées. |
| Iframe | Non | Intègre le contenu externe configuré dans le chat. |
| API request | Non | Appelle un point de terminaison HTTP, saisi sous la forme d'une URL ou nommé dans une définition Swagger/OpenAPI, et mappe son résultat. |
| Send email | Non | Envoie un e-mail via le transport Resend configuré. |
| Improvement | Non | Crée une amélioration pour la réponse concernée. |
| Handover | Dépend de la cible | Poursuit une seule fois dans un autre Assistant publié. |
| HTTP webhook | Non | S'abonne à un système et attend son rappel. Voir [HTTP et webhooks](/flows/http). |
| Response | Non | Répond à la requête HTTP entrante qui a déclenché le Flow. Voir [HTTP et webhooks](/flows/http). |
| Connector | Non | Exécute une action dans ServiceNow, Salesforce, Slack, OneDrive ou Google Drive via une application connectée. Voir [Connector](/flows/connector). |
| Human review | Non | Interrompt le Flow jusqu'à ce qu'un collègue l'approuve par e-mail ou sur Slack. Voir [Human review](/flows/human-review). |

Le Basic Interaction Flow intégré utilise également **Basic reply**. La
recommandation du Help Desk utilise une action d'exécution que le sélecteur
d'actions directes n'affiche pas.

## Message

Saisissez le texte exact que Ciele doit envoyer. Le runtime ne paraphrase pas ce
texte. Les variables de modèle telles que `{{user.name}}` ou `{{review.amount}}`
sont remplacées par leurs valeurs.

## Réponse de base

La réponse de base prend en charge les salutations brèves, les remerciements et
les formules de congé. Elle utilise un seul appel de modèle et aucun outil
Knowledge, aucune citation ni aucun événement Thinking.

Saisissez un texte d'action fixe pour ignorer le modèle. Ce même texte sert de
solution de repli lorsqu'aucun modèle de chat n'est disponible.

## Recherche dans la base de connaissances

Search knowledge utilise les outils Knowledge disponibles jusqu'à la limite
d'étapes d'exécution. Il peut renvoyer des citations de sources nommées et des
étapes de raisonnement (Thinking Steps).

Utilisez ses paramètres unresolved-query pour proposer une remontée au Help Desk
ou créer une Improvement.

**Search guidelines** indique à la recherche ce qu'il faut chercher. **Answering
style** définit le ton et le format de cette réponse. Chaque champ accepte
jusqu'à 10 000 caractères.

Par défaut, le style de réponse de l'action s'ajoute au style de l'Assistant.
Sélectionnez **Override answering style** pour remplacer le style de l'Assistant
pour cette action.

## Bouton

Configurez un label et une cible. Une cible peut ouvrir un lien ou envoyer du
texte configuré dans la Conversation.

## Questions de suivi

Saisissez des questions de suivi prédéfinies ou activez la génération. Les
questions de suivi générées utilisent le modèle rapide configuré.

## Iframe

Configurez le titre, le lien HTTPS, la préférence de lightbox et la hauteur. Le
site hôte peut toujours empêcher l'intégration par le biais de ses en-têtes de
sécurité.

## Requête API

La requête API effectue un appel HTTP. Configurez l'authentification, les
en-têtes, les paramètres de requête, le corps JSON et le chemin JSON de la
réponse, puis choisissez la provenance du point de terminaison sous
**Endpoint**.

**A URL** prend une méthode et une URL de point de terminaison que vous
saisissez.

**An operation in a Swagger/OpenAPI definition** prend un **Swagger URL** et un
**Operation ID**. Ciele lit la définition lorsque l'action s'exécute, et en
extrait la méthode et l'URL. Le Flow continue de fonctionner lorsque l'API
change de localisation. La définition est lue à chaque exécution et n'est pas
mise en cache. Un paramètre de chemin tel que `{refundId}` devient la variable
de modèle `{{refundId}}`, de sorte qu'une action antérieure peut fournir sa
valeur. La définition doit placer l'API sur le même site que la définition
elle-même. Une définition servie depuis `docs.example.com` peut être nommée
`api.example.com`. Un autre domaine est refusé. Cela permet de conserver les
informations d'identification de l'action sur le site que vous avez configuré.

Les variables de modèle peuvent fournir des valeurs issues du contexte actuel.
Utilisez **Test API** avant d'enregistrer le Flow.

L'action peut afficher des messages distincts pour la réussite et l'échec. Les
règles de sortie réseau s'appliquent à l'URL finale et à l'URL Swagger.

## Webhook HTTP

Le webhook HTTP s'abonne à un système externe, interrompt le Flow et reprend son
exécution lorsque ce système effectue un rappel. Configurez l'appel
d'abonnement, l'appel de désabonnement, la durée d'attente et ce que le Visiteur
lit pendant ce temps.

Insérez `{{webhook.callbackUrl}}` dans l'URI ou le corps de la requête
d'abonnement. C'est ainsi que l'autre système apprend où répondre. Le corps du
rappel atteint les actions ultérieures sous la forme de `{{webhook.body}}`.
**Response mapping** en extrait les valeurs nommées.

Le comportement complet, y compris ce que l'adresse de rappel autorise, est
décrit dans [HTTP and webhooks](/flows/http).

## Réponse

Response répond à la requête HTTP entrante qui a déclenché le Flow, avec un code
de statut ainsi que des en-têtes et un corps optionnels. Elle n'est disponible
que sur le déclencheur **On HTTP request** et met fin au Flow.

Voir [HTTP and webhooks](/flows/http).

## Envoyer un e-mail

Configurez les destinataires, l'objet, le corps du message et le comportement de
l'adresse de réponse. L'environnement d'exécution utilise Resend lorsque son
transport est configuré.

Lorsque le transport n'est pas configuré, l'action indique qu'elle n'a pas
envoyé l'e-mail. Elle ne revendique pas la remise.

## Amélioration

L'action crée une tâche d'amélioration. Elle n'ajoute pas d'elle-même de texte
de réponse visible.

## Transfert

Sélectionnez un autre Assistant dans la même Organisation. La cible doit avoir
une Publication en cours.

Ciele fait passer le même message de visiteur par l'Assistant cible une seule
fois. Il n'effectue pas de second transfert à partir de ce tour cible.

## Connecteur

Sélectionnez une application connectée, une connexion et une action cataloguée.
Le Flow stocke l'identifiant de connexion et l'action, mais jamais d'identifiant
de connexion.

Les résultats deviennent des variables de template `{{connector.*}}` pour des
actions ultérieures. Consultez [Connector](/flows/connector) pour accéder au
catalogue, aux champs et à ce que le Visitor voit.

## Vérification humaine

Indiquez les noms des reviewers, le channel et les inputs qu'ils renseignent. Le
Flow s'arrête à cette action et ne se poursuit qu'après approbation. Les entrées
du reviewer deviennent des variables de template `{{review.*}}`. Voir
[Human review](/flows/human-review).

## Ordre des actions

Insérez un texte d'encadrement avant Search knowledge. Placez les boutons et les
actions de suivi après la réponse qu'ils concernent.
