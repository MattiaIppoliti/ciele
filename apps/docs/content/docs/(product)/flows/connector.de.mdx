## Was ein Connector tut

Ein **Connector** ist eine Antwortaktion. Es führt eine Aktion in einem System
aus, das Ihre Organisation bereits unter **Knowledge → Applications** verbunden
hat. Der Flow speichert die Verbindung und die Aktion. Es werden niemals
Anmeldeinformationen gespeichert.

Verfügbare Aktionen:

| Provider | Actions |
| --- | --- |
| ServiceNow | Create record, Update record, List records, Delete record |
| Salesforce | Get Contact records, Get Case records, Get User records, Get Product records, Create case, Update case |
| Slack | Nachricht posten, Kanal erstellen, Öffentlichem Kanal beitreten, Öffentliche Kanäle auflisten |
| OneDrive | Create file, Copy file, Find files in folder, Get file content, Get file metadata, Create share link, Delete file |
| Google Drive | Create file, Copy file, Find files in folder, Get file content, Get file metadata, Create share link, Delete file |

Jede Aktion ist entweder ein **read** oder ein **write**. Ein Schreibvorgang
ändert das externe System.

## OneDrive und Google Drive

Eine OneDrive- oder Google-Drive-Verbindung gehört einem einzigen Member. Der
Connector wird unter dem Konto dieses Members ausgeführt. Aus diesem Grund:

- Die Aktion wird im **Preview** und im **Teammate chat** ausgeführt. Es wird
  nicht in einem veröffentlichten Widget ausgeführt.
- **Publish** lehnt einen Flow ab, der einen Drive-Connector enthält. Der Grund
  nennt den Flow.
- Write-Aktionen benötigen einen zusätzlichen Scope. OneDrive benötigt
  `Files.ReadWrite`. Google Drive benötigt `drive.file`. Wählen Sie **Grant
  access** aus, um es hinzuzufügen.
- Mit `drive.file` erlaubt Google Drive dem Connector, nur Dateien zu ändern,
  die der Connector selbst erstellt hat oder die eine Person mit ihm geöffnet
  hat. Copy, Share und Delete können bei anderen Dateien fehlschlagen.
- **Get file content** gibt nur Text zurück, bis zu einer festgelegten Größe.
  Binärdateien und Google Docs werden nicht konvertiert.

## Einen Connector hinzufügen

1. Öffnen Sie einen Flow.
2. Wählen Sie im **Canvas** einen Provider unter **Connector** in der Palette
   aus. Wählen Sie im **Form** unter **Add an action** die Option **Connector**
   aus und wählen Sie anschließend den Provider aus.
3. Wählen Sie ein **Connection** aus. Die Liste zeigt die Verbindungen der
   Organisation für diesen Provider an.
4. Wählen Sie ein **Action** aus.
5. Füllen Sie die Felder aus. Template-Variablen wie `{{user.name}}` und
   `{{workflow.message}}` sind dort zulässig, wo das Feld dies angibt.

Wenn der Provider keine Verbindung hat, verbinden Sie ihn zuerst unter
**Knowledge → Applications**. Bei Slack kann das Panel das Anmeldefenster direkt
öffnen.

## Salesforce-Fälle

**Create case** öffnet einen Case in der verbundenen Salesforce-Organisation.
**Update case** ändert einen vorhandenen Case.

- Die Felder sind **Subject**, **Description**, **Priority**, **Status**,
  **Origin**, **Requester email** und **Requester name**. Jedes Feld akzeptiert
  Vorlagenvariablen.
- **Create case** setzt **Origin** standardmäßig auf `Web`. Ein leeres Feld
  behält den Salesforce-Standardwert bei.
- **Requester email** und **Requester name** werden in die Felder „web email“
  und „web name“ des Case eingetragen. Ein Visitor, der kein Salesforce Contact
  ist, kann einen Case eröffnen.
- **Update case** benötigt ein **Case id**. In der Regel handelt es sich dabei
  um `{{connector.case_id}}` aus einem früheren **Create case**. Es ändern sich
  nur die Felder, die Sie ausfüllen.
- Der Salesforce-Benutzer, der die Anwendung verbunden hat, muss über die
  Berechtigung **Create** für Cases für **Create case** sowie über die
  Berechtigung **Edit** für **Update case** verfügen. Die Verbindung benötigt
  keinen neuen Scope.

Wenn Salesforce den Case ablehnt, beispielsweise weil ein Pflichtfeld leer ist
oder eine Validierungsregel fehlschlägt, schlägt die Aktion fehl. Die
Salesforce-Meldung wird in **Run node** und in der Conversation Trace angezeigt.
Der Flow wird mit seiner üblichen Fehlerregel fortgesetzt.

Nach einem Schreibvorgang liest Ciele die Case-Nummer. Wenn dieser Lesevorgang
fehlschlägt, ist der Schreibvorgang dennoch erfolgreich und behält die Case ID
sowie den Link bei. Die Nummer ist leer. Verwenden Sie **Get Case records** mit
dieser ID und das Feld `CaseNumber`, um es später auszulesen.

## Vom System geladene Felder

Einige Felder laden ihre Werte aus dem verbundenen System: ServiceNow-Tabellen
und -Spalten, Salesforce-Felder, die Salesforce-Case-Auswahllisten (Priority,
Status, Origin) sowie Slack-Kanäle. Wählen Sie **Load options** aus, um sie
abzurufen. Sie können weiterhin einen Wert eingeben.

## Einrichtung erforderlich

Ein Connector-Knoten zeigt **Needs setup** an, wenn:

- Die Aktion oder die Verbindung ist nicht ausgewählt.
- Ein Pflichtfeld ist leer.
- Der Verbindung fehlt ein Scope, den die Aktion benötigt. Wählen Sie **Grant
  access** aus, um die Anmeldung beim Provider erneut durchzuführen, wobei die
  fehlenden Scopes hinzugefügt werden.
- Die Verbindung muss erneut hergestellt werden.

## Ausgaben

Eine Aktion schreibt ihre Ergebnisse in Vorlagenvariablen für spätere Aktionen
im selben Flow. Die Namen beginnen mit `connector.`:

| Action | Variables |
| --- | --- |
| ServiceNow – Datensatz erstellen oder aktualisieren | `{{connector.sys_id}}`, `{{connector.number}}`, `{{connector.url}}` (ein Link zum Datensatz) |
| ServiceNow – Datensätze auflisten | `{{connector.count}}`, `{{connector.first_sys_id}}`, `{{connector.records}}` |
| Salesforce Get records | `{{connector.count}}`, `{{connector.first_id}}`, `{{connector.records}}`, `{{connector.api_usage}}` |
| Salesforce Fall erstellen oder aktualisieren | `{{connector.case_id}}`, `{{connector.case_number}}`, `{{connector.case_url}}` (ein Link zum Fall in Salesforce) |
| Slack Nachricht posten | `{{connector.ts}}`, `{{connector.channel}}` |
| Slack Kanal erstellen oder beitreten | `{{connector.id}}`, `{{connector.name}}` |
| Drive Metadaten erstellen oder abrufen, Google Drive Kopieren | `{{connector.id}}`, `{{connector.name}}`, `{{connector.web_url}}` |
| OneDrive Copy | `{{connector.status}}`, `{{connector.monitor_url}}` (der Kopiervorgang läuft im Hintergrund) |
| Drive Find files | `{{connector.count}}`, `{{connector.first_id}}`, `{{connector.items}}` |
| Drive Get content | `{{connector.content}}` |
| Drive Freigabelink erstellen | `{{connector.url}}` |

`{{connector.ok}}` ist nach jeder Aktion `true` oder `false`. Eine
**Message**-Aktion nach dem Connector kann diese Werte anzeigen.

## Was der Besucher sieht

- Ein erfolgreicher **write** zeigt das **Success message** an. Standardmäßig
  wird eine kurze Bestätigung angezeigt.
- Ein erfolgreiches **read** zeigt nichts an. Verwenden Sie eine Message-Aktion,
  um die Ergebnisse anzuzeigen.
- Bei jedem Fehler wird **Failure message** angezeigt. Der Fehler des Providers
  wird dem Visitor niemals angezeigt. Der Editor sieht es in **Run node** und –
  bei einer abgelaufenen Verbindung – in **Alerts**.

## Knoten ausführen

Wählen Sie den Knoten aus und klicken Sie anschließend auf **Run node**. Die
Konsole führt den tatsächlichen Aufruf mit Beispielwerten durch.

- Ein **read** wird sofort ausgeführt.
- Ein **write** fordert zunächst eine Bestätigung an, da es das externe System
  verändert.

**Test connection** überprüft, ob das Token der Verbindung noch funktioniert.

## Veröffentlichen

Publish lehnt einen Flow ab, dessen Connector:

- eine Verbindung benennt, die nicht mehr existiert,
- eine persönliche Verbindung benennt (OneDrive- oder Google-Drive-Konten
  gehören zu einem einzelnen Mitglied),
- eine Verbindung benennt, der die Scopes der Aktion fehlen oder die erneut
  verbunden werden muss.

Der Grund gibt dem Flow seinen Namen. Beheben Sie das Problem mit der Verbindung
oder dem Flow und veröffentlichen Sie dann erneut.

## Abgelaufene Verbindungen

Wenn ein Aufruf fehlschlägt, weil der Provider das Token abgelehnt hat, wird die
Verbindung als **Reauthorization required** markiert und eine
**Integration**-Warnung ausgelöst. Verbinden Sie die Anwendung erneut unter
**Knowledge → Applications**. Die Warnmeldung wird bei erneuter Verbindung
aufgehoben.

## API, CLI und MCP

- `GET /api/v1/applications/connections` listet die Verbindungen ohne
  Anmeldeinformationen auf.
- `GET /api/v1/applications/connectors` listet den Katalog auf.
- `POST /api/v1/applications/connections/{id}/reconsent` gibt die
  Scope-Vereinigung sowie die URL zurück, die geöffnet werden muss, um sie zu
  gewähren.

Die gleichen Operationen sind `ciele applications list|connectors|reconsent` und
die `manage_integrations` MCP-Tool-Aktionen `application_list`,
`application_connectors`, `application_reconsent`.
