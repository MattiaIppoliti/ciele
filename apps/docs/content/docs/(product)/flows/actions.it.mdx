---
title: Azioni del flusso
description: Seleziona le azioni di risposta che il runtime corrente può eseguire.
---

Le azioni del flusso dei messaggi vengono eseguite in ordine. Le azioni non
generative utilizzano il contenuto configurato senza che il modello lo riscriva.

## Azioni disponibili

| Action | Model use | Current behavior |
| --- | :---: | --- |
| Message | No | Emette il testo configurato parola per parola. |
| Button | No | Aggiunge un pulsante di collegamento oppure un pulsante che invia testo nella chat. |
| Search knowledge | Yes | Esegue il ciclo dell'agente Knowledge e restituisce le citazioni. |
| Follow-ups | Optional | Utilizza le domande configurate o genera domande suggerite. |
| Iframe | No | Incorpora nel chat il contenuto esterno configurato. |
| API request | No | Chiama un endpoint HTTP, inserito come URL o denominato in una definizione Swagger/OpenAPI, e ne associa il risultato. |
| Send email | No | Invia un'email tramite il trasporto Resend configurato. |
| Improvement | No | Crea un Improvement per la risposta pertinente. |
| Handover | Dipende dalla destinazione | Prosegue una sola volta in un altro Assistente pubblicato. |
| HTTP webhook | No | Si iscrive a un sistema e attende il suo callback. Consulta [HTTP and webhooks](/flows/http). |
| Response | No | Risponde alla richiesta HTTP in entrata che ha avviato il Flow. Consulta [HTTP and webhooks](/flows/http). |
| Connector | No | Esegue una singola azione in ServiceNow, Salesforce, Slack, OneDrive o Google Drive tramite un'applicazione connessa. Vedi [Connector](/flows/connector). |
| Human review | No | Interrompe il Flow fino all'approvazione di un collega tramite email o Slack. Consulta [Human review](/flows/human-review). |

Anche il Basic Interaction Flow integrato utilizza **Basic reply**. La
raccomandazione dell'Help Desk utilizza un'azione runtime che il selettore di
azioni dirette non mostra.

## Message

Inserisci il testo esatto che Ciele deve inviare. Il runtime non parafrasa
questo testo. Le variabili del template, come `{{user.name}}` o
`{{review.amount}}`, vengono sostituite con i loro valori.

## Risposta di base

La risposta di base gestisce brevi saluti, ringraziamenti e congedi. Utilizza
una sola chiamata al modello e nessun Knowledge tool, nessuna citazione e nessun
Thinking event.

Inserisci il testo dell'azione fissa per saltare il modello. Lo stesso testo
funge da fallback quando non è disponibile alcun modello di chat.

## Ricerca nella knowledge base

Search knowledge utilizza gli strumenti Knowledge disponibili fino al
raggiungimento del limite di passaggi di runtime. Può restituire citazioni di
fonti denominate e Thinking Steps.

Utilizza le sue impostazioni unresolved-query per offrire l'escalation all'Help
Desk o per creare un Improvement.

**Search guidelines** indica alla ricerca cosa cercare. **Answering style**
definisce il tono e il formato di questa risposta. Ogni campo accetta fino a
10.000 caratteri.

Per impostazione predefinita, lo stile di risposta dell'azione si aggiunge allo
stile dell'Assistente. Seleziona **Override answering style** per sostituire lo
stile dell'Assistente per questa azione.

## Pulsante

Configura una label e un target. Un target può aprire un link oppure inviare il
testo configurato nella Conversation.

## Domande di follow-up

Inserisci domande di follow-up predefinite oppure abilita la generazione. Le
domande di follow-up generate utilizzano il modello fast configurato.

## Iframe

Configura il titolo, il link HTTPS, la preferenza per la lightbox e l'altezza.
Il sito host può comunque impedire l'embedding tramite i suoi security header.

## Richiesta API

La richiesta API effettua una singola chiamata HTTP. Configura l'autenticazione,
gli header, i parametri di query, il corpo JSON e il percorso JSON della
risposta, e scegli da dove proviene l'endpoint in **Endpoint**.

**A URL** accetta un metodo e un URL dell'endpoint che inserisci.

**An operation in a Swagger/OpenAPI definition** accetta un **Swagger URL** e un
**Operation ID**. Ciele legge la definizione quando l'azione viene eseguita e ne
estrae il metodo e l'URL. Il Flow continua a funzionare quando l'API viene
spostata. La definizione viene letta a ogni esecuzione e non viene memorizzata
nella cache. Un parametro di percorso come `{refundId}` diventa la variabile di
template `{{refundId}}`, in modo che un'azione precedente possa fornirne il
valore. La definizione deve collocare l'API sullo stesso sito della definizione
stessa. Una definizione servita da `docs.example.com` può essere denominata
`api.example.com`. Un altro dominio viene rifiutato. In questo modo, le
credenziali dell'azione rimangono sul sito che hai configurato.

Le variabili di template possono fornire valori dal contesto corrente. Usa
**Test API** prima di salvare il Flow.

L'azione può mostrare messaggi separati per l'esito positivo e per l'esito
negativo. Le regole di uscita dalla rete si applicano all'URL finale e all'URL
Swagger.

## Webhook HTTP

L'HTTP webhook si iscrive a un sistema esterno, interrompe il Flow e riprende
quando quel sistema effettua il callback. Configura la chiamata di iscrizione,
la chiamata di cancellazione dell'iscrizione, il tempo di attesa e ciò che il
Visitor legge nel frattempo.

Inserisci `{{webhook.callbackUrl}}` nell'URI di sottoscrizione o nel body. È
così che l'altro sistema apprende dove rispondere. Il corpo del callback
raggiunge le azioni successive come `{{webhook.body}}`. **Response mapping** ne
estrae i valori denominati.

Il comportamento completo, incluso ciò che l'indirizzo di callback consente, è
descritto in [HTTP and webhooks](/flows/http).

## Response

Response risponde alla richiesta HTTP in entrata che ha avviato il Flow, con un
codice di stato e, facoltativamente, header e body. È disponibile solo sul
trigger **On HTTP request** e termina il Flow.

Consulta [HTTP and webhooks](/flows/http).

## Invia un'email

Configura i destinatari, l'oggetto, il corpo del messaggio e il comportamento
per l'indirizzo di risposta. Il runtime utilizza Resend quando il suo trasporto
è configurato.

Quando il trasporto non è configurato, l'azione segnala di non aver inviato
l'email. Non dichiara l'avvenuta consegna.

## Miglioramento

L'azione crea un'attività di tipo Improvement. Non aggiunge automaticamente
alcun testo di risposta visibile.

## Passaggio di consegne

Seleziona un altro Assistant nella stessa Organization. L'Assistente di
destinazione deve avere una Publication corrente.

Ciele fa passare una sola volta lo stesso messaggio del Visitor attraverso
l'Assistant di destinazione. Non prosegue con un secondo handover a partire da
quel turno di destinazione.

## Connettore

Seleziona un'applicazione connessa, una connessione e un'azione catalogata. Il
Flow memorizza l'ID della connessione e l'azione, mai una credenziale.

I risultati diventano variabili di template `{{connector.*}}` per azioni
successive. Consulta [Connector](/flows/connector) per il catalogo, i campi e
ciò che vede il Visitor.

## Revisione umana

Indica i revisori, il canale e gli input che compilano. Il Flow si interrompe a
questa azione e prosegue solo dopo l'approvazione. Gli input del revisore
diventano variabili di template `{{review.*}}`. Consulta
[Human review](/flows/human-review).

## Ordine delle azioni

Inserisci il testo di inquadramento prima di Search knowledge. Posiziona i
pulsanti e i follow-up dopo la risposta che supportano.
