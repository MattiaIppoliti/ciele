## Rôle d’un connecteur

Un **Connector** est une action de réponse. Il exécute une action dans un
système que votre organisation a déjà connecté sous **Knowledge →
Applications**. Le Flow stocke la connexion et l'action. Il ne stocke jamais
d’identifiant de connexion.

Actions disponibles :

| Provider | Actions |
| --- | --- |
| ServiceNow | Create record, Update record, List records, Delete record |
| Salesforce | Get Contact records, Get Case records, Get User records, Get Product records, Create case, Update case |
| Slack | Publier un message, Créer un canal, Rejoindre un canal public, Lister les canaux publics |
| OneDrive | Create file, Copy file, Find files in folder, Get file content, Get file metadata, Create share link, Delete file |
| Google Drive | Create file, Copy file, Find files in folder, Get file content, Get file metadata, Create share link, Delete file |

Chaque action est une **lecture** ou une **écriture**. Une opération d’écriture
modifie le système externe.

## OneDrive et Google Drive

Une connexion OneDrive ou Google Drive appartient à un seul Membre. Le
connecteur s’exécute sous le compte de ce Membre. Pour cette raison :

- L'action s'exécute dans **Preview** et dans **Teammate chat**. Elle ne
  s’exécute pas dans un widget publié.
- **Publish** refuse un Flow qui contient un connecteur Drive. Le motif indique
  le nom du Flow.
- Les actions d’écriture nécessitent un scope supplémentaire. OneDrive nécessite
  `Files.ReadWrite`. Google Drive nécessite `drive.file`. Sélectionnez **Grant
  access** pour l’ajouter.
- Avec `drive.file`, Google Drive autorise le connecteur à modifier uniquement
  les fichiers qu’il a créés ou qu’une personne a ouverts avec lui. Les actions
  Copy, Share et Delete peuvent échouer sur d’autres fichiers.
- **Get file content** renvoie uniquement du texte, jusqu’à une taille limitée.
  Les fichiers binaires et les Google Docs ne sont pas convertis.

## Ajouter un connecteur

1. Ouvrez un Flow.
2. Dans le **Canvas**, sélectionnez un fournisseur sous **Connector** dans la
   palette. Dans le **Form**, sélectionnez **Connector** sous **Add an action**,
   puis sélectionnez le fournisseur.
3. Sélectionnez un **Connection**. La liste affiche les connexions de
   l’organisation pour ce fournisseur.
4. Sélectionnez un **Action**.
5. Remplissez les champs. Les variables de modèle telles que `{{user.name}}` et
   `{{workflow.message}}` sont autorisées lorsque le champ l’indique.

Si le fournisseur n’a pas de connexion, connectez-le d’abord sous **Knowledge →
Applications**. Pour Slack, le panneau peut ouvrir directement la fenêtre de
connexion.

## Dossiers Salesforce

**Create case** ouvre un Case dans l’organisation Salesforce connectée. **Update
case** modifie un Case existant.

- Les champs sont **Subject**, **Description**, **Priority**, **Status**,
  **Origin**, **Requester email** et **Requester name**. Chaque champ accepte
  des variables de template.
- **Create case** définit **Origin** sur `Web` par défaut. Un champ vide
  conserve la valeur par défaut de Salesforce.
- **Requester email** et **Requester name** sont renseignés dans les champs web
  email et web name du Case. Un Visitor qui n’est pas un Salesforce Contact peut
  ouvrir un Case.
- **Update case** nécessite un **Case id**. Généralement, il s'agit de
  `{{connector.case_id}}` provenant d'un **Create case** antérieur. Seuls les
  champs que vous renseignez changent.
- L’utilisateur Salesforce qui a connecté l’application doit disposer de
  l’autorisation **Create** sur les Cases pour **Create case**, ainsi que de
  l’autorisation **Edit** pour **Update case**. La connexion ne nécessite aucun
  nouveau scope.

Si Salesforce refuse la requête (Case), par exemple parce qu’un champ
obligatoire est vide ou qu’une règle de validation échoue, l’action échoue. Le
message Salesforce s’affiche dans **Run node** et dans la trace de conversation.
Le Flow poursuit avec sa règle d’échec habituelle.

Après une écriture, Ciele lit le numéro de Case. Si cette lecture échoue,
l’écriture réussit néanmoins et conserve l’identifiant du Case ainsi que le
lien. Le numéro est vide. Utilisez **Get Case records** avec cet identifiant et
le champ `CaseNumber` pour le lire ultérieurement.

## Champs chargés depuis le système

Certains champs chargent leurs valeurs à partir du système connecté : tables et
colonnes ServiceNow, champs Salesforce, listes de sélection des cas Salesforce
(Priority, Status, Origin), canaux Slack. Sélectionnez **Load options** pour les
récupérer. Vous pouvez toujours saisir une valeur.

## Configuration requise

Un nœud Connector affiche **Needs setup** lorsque :

- L’action ou la connexion n’est pas sélectionnée.
- Un champ obligatoire est vide.
- La connexion ne dispose pas d’un scope requis par l’action. Sélectionnez
  **Grant access** pour relancer la connexion au fournisseur en ajoutant les
  scopes manquants.
- La connexion doit être rétablie.

## Sorties

Une action écrit ses résultats dans des variables de template pour des actions
ultérieures dans le même Flow. Les noms commencent par `connector.` :

| Action | Variables |
| --- | --- |
| ServiceNow Create or Update record | `{{connector.sys_id}}`, `{{connector.number}}`, `{{connector.url}}` (un lien vers l’enregistrement) |
| ServiceNow List records | `{{connector.count}}`, `{{connector.first_sys_id}}`, `{{connector.records}}` |
| Salesforce Get records | `{{connector.count}}`, `{{connector.first_id}}`, `{{connector.records}}`, `{{connector.api_usage}}` |
| Salesforce : Créer ou mettre à jour une requête | `{{connector.case_id}}`, `{{connector.case_number}}`, `{{connector.case_url}}` (un lien vers la requête dans Salesforce) |
| Slack Post message | `{{connector.ts}}`, `{{connector.channel}}` |
| Slack Créer ou rejoindre un canal | `{{connector.id}}`, `{{connector.name}}` |
| Drive Créer ou obtenir des métadonnées, Google Drive Copier | `{{connector.id}}`, `{{connector.name}}`, `{{connector.web_url}}` |
| OneDrive Copy | `{{connector.status}}`, `{{connector.monitor_url}}` (la copie s’exécute en arrière-plan) |
| Drive Find files | `{{connector.count}}`, `{{connector.first_id}}`, `{{connector.items}}` |
| Drive Get content | `{{connector.content}}` |
| Drive Create share link | `{{connector.url}}` |

`{{connector.ok}}` est `true` ou `false` après chaque action. Une action
**Message** après le Connector peut afficher ces valeurs.

## Ce que le visiteur voit

- Une opération **write** qui réussit affiche le **Success message**. La valeur
  par défaut est une brève confirmation.
- Une action **read** qui réussit n’affiche rien. Utilisez une action Message
  pour afficher les résultats.
- Tout échec affiche le **Failure message**. L’erreur du fournisseur n’est
  jamais présentée au Visitor. L’Editor le voit dans **Run node** et, dans le
  cas d’une connexion expirée, dans **Alerts**.

## Exécuter le nœud

Sélectionnez le nœud, puis **Run node**. La console effectue l’appel réel avec
des valeurs d’exemple.

- Une opération **read** s'exécute immédiatement.
- Une opération **write** demande d’abord une confirmation, car elle modifie le
  système externe.

**Test connection** vérifie que le token de la connexion fonctionne toujours.

## Publier

Publish refuse un Flow dont le Connector :

- désigne une connexion qui n'existe plus,
- désigne une connexion personnelle (les comptes OneDrive ou Google Drive
  appartiennent à un seul Membre),
- désigne une connexion qui ne dispose pas des portées requises pour l'action ou
  qui doit être reconnectée.

Le motif donne son nom au Flow. Corrigez la connexion ou le Flow, puis
republiez.

## Connexions expirées

Lorsqu’un appel échoue parce que le fournisseur a rejeté le token, la connexion
est marquée **Reauthorization required** et une alerte **Integration** est
déclenchée. Reconnectez l’application sous **Knowledge → Applications**.
L’alerte disparaît lors de la reconnexion.

## API, CLI et MCP

- `GET /api/v1/applications/connections` répertorie les connexions sans
  identifiants.
- `GET /api/v1/applications/connectors` répertorie le catalogue.
- `POST /api/v1/applications/connections/{id}/reconsent` renvoie l’union des
  portées et l’URL à ouvrir pour l’accorder.

Les mêmes opérations sont `ciele applications list|connectors|reconsent` et les
actions de l’outil MCP `manage_integrations` `application_list`,
`application_connectors`, `application_reconsent`.
