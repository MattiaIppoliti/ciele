Message Flow-Aktionen werden in der angegebenen Reihenfolge ausgeführt.
Nicht-generative Aktionen verwenden den konfigurierten Inhalt, ohne dass das
Modell ihn umschreibt.

## Verfügbare Aktionen

| Action | Model use | Current behavior |
| --- | :---: | --- |
| Message | No | Gibt den konfigurierten Text wörtlich aus. |
| Button | No | Fügt eine Schaltfläche mit Link hinzu oder eine Schaltfläche, die Text in den Chat sendet. |
| Search knowledge | Yes | Führt die Knowledge-Agent-Schleife aus und gibt Quellenangaben zurück. |
| Follow-ups | Optional | Verwendet konfigurierte Fragen oder generiert vorgeschlagene Fragen. |
| Iframe | Nein | Bettet konfigurierten externen Inhalt in den Chat ein. |
| API request | Nein | Ruft einen HTTP-Endpunkt auf, der als URL eingegeben oder in einer Swagger-/OpenAPI-Definition benannt ist, und ordnet dessen Ergebnis zu. |
| Send email | Nein | Sendet eine E-Mail über den konfigurierten Resend-Transport. |
| Improvement | Nein | Erstellt eine Verbesserung für die betreffende Antwort. |
| Handover | Hängt vom Ziel ab | Wird einmal in einem anderen veröffentlichten Assistant fortgesetzt. |
| HTTP webhook | Nein | Aboniert ein System und wartet auf dessen Callback. Siehe [HTTP and webhooks](/flows/http). |
| Response | Nein | Beantwortet die eingehende HTTP-Anfrage, die den Flow gestartet hat. Siehe [HTTP and webhooks](/flows/http). |
| Connector | Nein | Führt eine Aktion in ServiceNow, Salesforce, Slack, OneDrive oder Google Drive über eine verbundene Anwendung aus. Siehe [Connector](/flows/connector). |
| Human review | Nein | Hält den Flow an, bis ein Kollege per E-Mail oder Slack zustimmt. Siehe [Human review](/flows/human-review). |

Der integrierte Basic Interaction Flow verwendet ebenfalls **Basic reply**. Die
Help-Desk-Empfehlung verwendet eine Runtime-Aktion, die im Direct Action Picker
nicht angezeigt wird.

## Nachricht

Geben Sie den exakten Text ein, den Ciele senden muss. Die Runtime formuliert
diesen Text nicht um. Template-Variablen wie `{{user.name}}` oder
`{{review.amount}}` werden durch ihre Werte ersetzt.

## Einfache Antwort

Basic reply verarbeitet kurze Begrüßungen, Danksagungen und Verabschiedungen. Es
verwendet einen einzigen Modellaufruf und keine Knowledge-Tools, keine Zitate
und keine Thinking-Ereignisse.

Geben Sie einen festen Aktionstext ein, um das Modell zu überspringen. Derselbe
Text dient als Fallback, wenn kein Chat-Modell verfügbar ist.

## Wissen durchsuchen

Search Knowledge verwendet die verfügbaren Knowledge-Tools bis zum Erreichen des
Limits für Runtime-Schritte. Es kann benannte Source-Zitate und Thinking Steps
zurückgeben.

Verwenden Sie die Einstellungen für unresolved-query, um eine Eskalation an den
Help Desk anzubieten oder eine Verbesserung zu erstellen.

**Search guidelines** gibt der Suche vor, wonach gesucht werden soll.
**Answering style** legt den Ton und das Format dieser Antwort fest. Jedes Feld
akzeptiert bis zu 10.000 Zeichen.

Standardmäßig ergänzt der Answering-Stil der Aktion den Assistant-Stil. Wählen
Sie **Override answering style**, um den Assistant-Stil für diese Aktion zu
ersetzen.

## Schaltfläche

Konfigurieren Sie ein Label und ein Target. Ein Target kann einen Link öffnen
oder konfigurierten Text in die Conversation senden.

## Follow-ups

Geben Sie feste Folgefragen ein oder aktivieren Sie die Generierung. Generierte
Folgefragen verwenden das konfigurierte Fast-Modell.

## Iframe

Konfigurieren Sie den Titel, den HTTPS-Link, die Lightbox-Einstellung und die
Höhe. Die Host-Website kann das Einbetten nach wie vor über ihre Security
Headers verhindern.

## API-Anfrage

Eine API-Anfrage führt einen HTTP-Aufruf aus. Konfigurieren Sie die
Authentifizierung, die Header, die Query-Parameter, den JSON-Body und den
JSON-Pfad der Antwort, und wählen Sie unter **Endpoint** aus, woher der Endpoint
stammt.

**A URL** verwendet eine von Ihnen eingegebene Methode und eine von Ihnen
eingegebene Endpoint-URL.

**An operation in a Swagger/OpenAPI definition** erwartet ein **Swagger URL**
und ein **Operation ID**. Ciele liest die Definition, wenn die Aktion ausgeführt
wird, und entnimmt ihr die Methode und die URL. Der Flow funktioniert auch dann
weiter, wenn die API umgezogen wird. Die Definition wird bei jedem Ausführen
gelesen und wird nicht zwischengespeichert. Ein Pfadparameter wie `{refundId}`
wird zur Vorlagenvariable `{{refundId}}`, sodass eine frühere Aktion ihren Wert
bereitstellen kann. Die Definition muss die API auf derselben Site platzieren
wie die Definition selbst. Eine Definition, die von `docs.example.com`
bereitgestellt wird, darf `api.example.com` heißen. Eine andere Domain wird
abgelehnt. Dadurch bleiben die Anmeldeinformationen der Aktion auf der von Ihnen
konfigurierten Site erhalten.

Template-Variablen können Werte aus dem aktuellen Kontext bereitstellen.
Verwenden Sie **Test API**, bevor Sie den Flow speichern.

Die Aktion kann separate Meldungen für Erfolg und Fehler anzeigen.
Netzwerk-Egress-Regeln gelten für die endgültige URL und für die Swagger-URL.

## HTTP-Webhook

Der HTTP-Webhook abonniert ein externes System, hält den Flow an und setzt ihn
fort, wenn dieses System einen Rückruf durchführt. Konfigurieren Sie den
Subscribe-Aufruf, den Unsubscribe-Aufruf, die Wartezeit und den Text, den der
Visitor in der Zwischenzeit liest.

Fügen Sie `{{webhook.callbackUrl}}` in den Subscribe-URI oder den Body ein. Auf
diese Weise erfährt das andere System, wohin es antworten soll. Der
Callback-Body erreicht nachfolgende Aktionen als `{{webhook.body}}`. **Response
mapping** extrahiert daraus benannte Werte.

Das vollständige Verhalten, einschließlich dessen, was die Callback-Adresse
zulässt, ist unter [HTTP und Webhooks](/flows/http) beschrieben.

## Response

Response beantwortet die eingehende HTTP-Anfrage, die den Flow gestartet hat,
mit einem Statuscode sowie optionalen Headern und einem optionalen Body. Es ist
nur beim Trigger **On HTTP request** verfügbar und beendet den Flow.

Siehe [HTTP and webhooks](/flows/http).

## E-Mail senden

Konfigurieren Sie Empfänger, Betreff, Textkörper und das Verhalten bei
Antworten. Die Runtime verwendet Resend, wenn ihr Transport konfiguriert ist.

Wenn der Transport nicht konfiguriert ist, meldet die Aktion, dass sie die
E-Mail nicht gesendet hat. Es erhebt keinen Anspruch auf Zustellung.

## Verbesserung

Die Aktion erstellt eine Aufgabe vom Typ „Improvement“. Sie fügt keinen
sichtbaren Antworttext von sich aus hinzu.

## Übergabe

Wählen Sie einen anderen Assistant in derselben Organization aus. Das Ziel muss
über eine aktuelle Publication verfügen.

Ciele leitet dieselbe Visitor-Nachricht einmal durch den Ziel-Assistenten. Es
wird keine zweite Übergabe ausgehend von diesem Zielzug fortgesetzt.

## Connector

Wählen Sie eine verbundene Anwendung, eine Verbindung und eine katalogisierte
Aktion aus. Der Flow speichert die connection id und die action, niemals jedoch
Anmeldeinformationen.

Die Ergebnisse werden zu `{{connector.*}}`-Template-Variablen für spätere
Aktionen. Siehe [Connector](/flows/connector) für den Katalog, die Felder und
das, was der Visitor sieht.

## Überprüfung durch Menschen

Geben Sie die Prüfer, den Kanal und die von ihnen auszufüllenden Eingabefelder
an. Der Flow hält bei dieser Aktion an und wird erst nach Genehmigung
fortgesetzt. Die Eingaben des Reviewers werden zu
`{{review.*}}`-Template-Variablen. Siehe [Human review](/flows/human-review).

## Reihenfolge der Aktionen

Platzieren Sie den Rahmenstext vor Search knowledge. Platzieren Sie Buttons und
Follow-ups nach der Antwort, die sie unterstützen.
