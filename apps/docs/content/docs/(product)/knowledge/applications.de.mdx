Application Knowledge kopiert ausgewählte externe Inhalte in Ciele als
durchsuchbare Sources. Jede Source durchläuft den normalen Ingestionspfad, wird
in Citations angezeigt und liefert Antworten nur für die verknüpften Assistants.
Die Integration erfolgt direkt. Es verwendet weder Merge noch einen anderen
Integrationsbroker.

<Callout title="Content is copied into Ciele">
  Ciele applies the Assistant links that you configure. It does not recheck the source system's
  per-user permissions when a Visitor asks a question. Select only content that every intended
  audience may receive.
</Callout>

## Verbindung, Import und Quelle

Ein **Application Connection** speichert ein autorisiertes externes Konto. Ein
**Application Import** wählt Inhalte innerhalb dieses Kontos, einen Zeitplan
sowie die Assistenten aus, die darin suchen dürfen. Eine Synchronisierung
erstellt oder aktualisiert für jedes Remote-Element eine Ciele Source.

Verwenden Sie eine einzige Connection für mehrere Imports, wenn deren Scope oder
die Verknüpfungen zu den Assistants unterschiedlich sind. Beispielsweise kann
eine Slack Connection separate Kanalgruppen an verschiedene Assistants
übermitteln.

Salesforce-, ServiceNow- und Slack-Connections gehören zur Organisation. Jede
Organisation kann für jeden dieser Anbieter eine Connection haben. OneDrive- und
Google Drive-Connections gehören dem Member, der sie autorisiert. Jedes Mitglied
kann für jeden persönlichen Anbieter ein Konto verbinden.

Ein Organization Admin kann Metadaten persönlicher Verbindungen einsehen und
eine persönliche Verbindung entfernen. Nur das besitzende Mitglied kann sie
erneut verbinden. Anmeldedaten des Providers überschreiten niemals die Grenze
des Members. Importierte Quellen zählen zum Wissen der Organisation und folgen
den für sie konfigurierten Assistant-Links.

## Ein Konto verbinden

Ein Organization Admin oder Owner kann Salesforce, ServiceNow oder Slack
verbinden. Ein Mitglied mit der Berechtigung „Knowledge edit“ kann sein OneDrive
oder Google Drive verbinden und Importe verwalten.

1. Öffnen Sie **Library** und wählen Sie **Applications** aus, oder öffnen Sie
   die **Knowledge** eines Assistenten und wählen Sie **Applications** aus.
2. Wählen Sie **Connect** beim Anbieter aus.
3. Geben Sie für Salesforce oder ServiceNow einen Connection-Namen, die
   Instance-URL, die Client-ID und das Client-Secret ein.
4. Wählen Sie für Slack, OneDrive oder Google Drive **Continue connecting** auf
   der Verbindungsseite von Ciele aus.
5. Melden Sie sich auf der Website des Providers an und genehmigen Sie den
   Zugriff. Ciele aktualisiert anschließend die Liste „Applications“.
6. Erstellen Sie einen Import, wählen Sie dessen Scope aus und verknüpfen Sie
   mindestens einen Assistant.
7. Wählen Sie die Synchronisierung **Daily** oder **Manual**.
8. Speichern Sie den Import und warten Sie, bis seine Sources den Status
   **Ready** erreichen.
9. Testen Sie eine Antwort und öffnen Sie die zugehörige benannte Source-Angabe.

Slack, OneDrive und Google Drive fordern Sie auf, sich anzumelden und den
Zugriff zu autorisieren. Mitglieder geben keine OAuth Client ID oder kein OAuth
Secret ein. Die Ciele-Bereitstellung stellt diese Anmeldeinformationen bereit.
**Not now** schließt das Verbindungsfenster, ohne ein Konto zu verbinden.

Der Assistant Editor zeigt Organization Imports an, die Sie verknüpfen können.
Die Library ist die vollständige Ansicht der Organisation und umfasst jeden
Import.

## Berechtigungsbereiche des Providers

| Provider | Auswählbarer Inhalt | Hinweise |
| --- | --- | --- |
| Salesforce | Knowledge-Sprache und bis zu drei Data Categories aus verschiedenen Gruppen | Verwenden Sie Production, Sandbox oder eine genehmigte My Domain. |
| ServiceNow | Eine oder mehrere Knowledge Bases und eine Sprache | Geben Sie die Instance-URL und den OAuth-Client ein, die von dieser ServiceNow-Instance bereitgestellt werden. Password grants werden nicht unterstützt. |
| Slack | Zugängliche Channels und ein Verlaufsfenster | Das Standardfenster umfasst 180 Tage. **All history** kann viele API-Aufrufe erfordern. Threads werden zusammen mit ihrer Root-Nachricht gespeichert. |
| OneDrive | Ein Laufwerk oder ein Ordner | Ciele importiert unterstützte Dateien über Microsoft Graph. SharePoint-Bibliotheken sind nicht Teil dieser ersten Version. |
| Google Drive | My Drive oder Shared Drive-Ordner | Native Google-Dokumente werden in ein lesbares Format exportiert. Andere unterstützte Dateien werden direkt heruntergeladen. |

Ciele meldet nicht unterstützte Dateien, leere Elemente und anbieterspezifische
Ausschlüsse als übersprungene Elemente. Ein fehlerhaftes Element verhindert
nicht, dass gültige Inhalte im selben Durchlauf verarbeitet werden.

## Synchronisierung und Status

Wählen Sie **Sync now** für eine sofortige Ausführung. **Pause** stoppt geplante
Ausführungen, ohne Quellen zu löschen. **Resume** stellt eine neue Ausführung in
die Warteschlange. Wenn Sie einen Scope bearbeiten, wird dessen Checkpoint
zurückgesetzt und eine vollständige Aktualisierung der neuen Auswahl geplant.

Die Tabelle **Configured imports** zeigt für jeden Import eine Zeile an. Die
Zeile zeigt den Status, die letzte und die nächste Synchronisierung, die Anzahl
der Dokumente sowie die Gesamtzahlen der aktualisierten und fehlgeschlagenen
Elemente des letzten Laufs an. Halten Sie den Mauszeiger über die Gesamtzahlen,
um die Anzahl der erkannten, entfernten und übersprungenen Elemente anzuzeigen.
Fehlgeschlagene Provider-Autorisierungen markieren die Connection für eine
erneute Verbindung und erzeugen einen Alert. Ein späterer erfolgreicher Lauf
löscht den Alert.

Wählen Sie einen Import oder dessen Anzahl an Dokumenten aus, um alle Elemente
anzuzeigen, die im Rahmen dieses Imports importiert wurden. Wählen Sie ein
Element aus, um sein Dokument mit den Registerkarten **Memories**, **Content**
und **Chunks** sowie seiner Zusammenfassung zu öffnen. Bei einem Element, das
Ciele noch nicht verarbeitet hat, wird stattdessen die Seite „Source“ geöffnet.

Während eine Synchronisierung läuft, zeigt die Konsole in der unteren rechten
Ecke eine Activity Card an. Die Karte zeigt die Anzahl der abgeschlossenen
Elemente und die Gesamtzahl an, zum Beispiel 261/291. Wählen Sie den Pfeil aus,
um maximal vier Elemente mit ihrem Status anzuzeigen. Elemente, bei denen ein
Fehler aufgetreten ist, werden zuerst angezeigt.

Die Remote-Identität bleibt stabil. Ein bearbeitetes Remote-Element aktualisiert
die vorhandene Source, sodass sich Links und Zitate nicht ändern. Ein entferntes
Remote-Element löscht seine aktive Source, behält jedoch einen internen
Tombstone bei. Dadurch kann bei einem späteren erneuten Auftreten der korrekte
Ersatz erstellt werden, ohne ihn zu duplizieren.

Provider-Ratenlimits verwenden die zurückgegebene Verzögerung für
Wiederholungsversuche. Daily Imports werden ebenfalls im Rahmen des normalen
Ciele-Worker-Zeitplans ausgeführt, sodass der Webprozess nicht geöffnet bleiben
muss.

## Auf Erwähnungen in Slack antworten

Slack Imports und Conversational Replies sind separate Funktionen. Imports
kopieren Wissen in Ciele. Conversational Replies führen einen veröffentlichten
Assistenten aus, wenn jemand `@Ciele` in einem aktivierten Kanal erwähnt.

1. Bitten Sie Ihren Bereitstellungsadministrator, die unten beschriebene Slack
   Events API zu konfigurieren.
2. Öffnen Sie die Slack Connection in **Applications** und wählen Sie **Slack
   assistant** aus.
3. Wählen Sie **Authorize conversational permissions** aus und genehmigen Sie
   den Zugriff in Slack. Import Connections können erst Beiträge
   veröffentlichen, wenn Sie diesen Schritt abgeschlossen haben.
4. Wählen Sie einen veröffentlichten Assistant aus Ihrer Organisation aus.
5. Laden Sie Ciele in jeden Kanal ein und wählen Sie dann das zulässige
   **Channels** aus der Liste aus. Kanäle, denen Ciele nicht beigetreten ist,
   sowie Slack Connect-Kanäle können nicht ausgewählt werden.
6. Wählen Sie **Save Slack assistant** aus.
7. Erwähnen Sie `@Ciele` mit einer Frage. Ciele antwortet im Thread dieser
   Nachricht.

Der Assistent verwendet seine verknüpften Wissensquellen, die veröffentlichte
Konfiguration und den aktuellen Slack-Kontext. Es liest bis zu 15
Channel-Nachrichten und 15 Thread-Nachrichten vor der Erwähnung.
Slack-Ratenbegrenzungen können diesen Kontext einschränken. Ciele liest bei
jeder Antwort nicht den gesamten Workspace. Ciele behandelt das Kanaltranskript
als nicht vertrauenswürdiges Referenzmaterial, nicht als Anweisungen. Jede
Person in einem Thread hat ihre eigene Ciele-Konversation. Diese Konversation
wird bei ihren späteren Erwähnungen im Thread fortgesetzt. Direct Messages lösen
diese Funktion nicht aus.

<Callout title="Choose the channel audience carefully">
  Everyone in an enabled channel can receive answers from the selected Assistant's knowledge.
  Ciele does not match Slack users to individual Source permissions or Ciele single sign-on identities.
  Assistants that require sign-in and shared channels are not supported.
  Use **Disable replies** to stop new replies without deleting Imports.
</Callout>

Jeder Slack-Workspace und jeder Slack-Kanal muss auf genau eine aktivierte
Verbindung zu einer Ciele-Organisation verweisen. Wenn zwei Organisationen
denselben Kanal aktivieren, antwortet Ciele dort nicht. Ciele löst in beiden
Organisationen eine Warnung aus, bis eine von ihnen den Kanal entfernt. Wenn Sie
eine Verbindung zu einem anderen Workspace oder einer anderen Slack-Anwendung
herstellen, wird die Konfiguration für Konversationen zurückgesetzt. Die
Slack-Verbindung muss derselben Slack-Anwendung angehören wie das
`SLACK_APPLICATION_APP_ID` der Bereitstellung. Andernfalls verweigert Ciele das
Speichern der Einstellungen.

### Konfigurieren Sie die Slack Events API

Führen Sie die Slack-Datenbankmigration durch, bevor Sie Events aktivieren.
Konfigurieren Sie diese nur serverseitigen Werte auf der **Basic
Information**-Seite von Slack:

```dotenv
SLACK_APPLICATION_APP_ID=
SLACK_SIGNING_SECRET=
```

Behalten Sie die vorhandene OAuth Client ID, das Client Secret und den HTTPS
OAuth Callback bei. Das Signing Secret unterscheidet sich vom Client Secret.
Speichern Sie keines der beiden Secrets jemals in einer öffentlichen
Umgebungsvariablen.

1. Fügen Sie `app_mentions:read` und `chat:write` unter **OAuth & Permissions**
   hinzu, zusätzlich zu den bereits vorhandenen Importberechtigungen.
2. Aktivieren Sie **Event Subscriptions** und setzen Sie die Request-URL auf
   `{origin}/api/slack/events`.
3. Abonnieren Sie das `app_mention`-Bot-Ereignis und speichern Sie die
   Konfiguration.
4. Konfigurieren Sie einen Organization-Modellanbieter, der den Traffic
   veröffentlichter Assistenten bedienen kann.

Ciele fordert die beiden Reply-Scopes nur dann an, wenn ein Member **Authorize
conversational permissions** auswählt. Eine Connection, die ausschließlich für
Imports verwendet wird, behält ein schreibgeschütztes Token.

Der Endpoint überprüft Slack-Signaturen und speichert jedes Event, bevor er es
bestätigt. Der Worker wird nach der Bestätigung ausgeführt und verwendet
dieselbe Conversation Runtime wie veröffentlichte Assistants. Abonnements
persönlicher Provider bedienen keinen Slack-Traffic.

Die Bereitstellung stellt außerdem `/api/cron/run-slack` bereit, geschützt durch
`CRON_SECRET`, für in der Warteschlange befindliche Wiederholungsversuche und
unterbrochene Worker. Der selbst gehostete Scheduler führt ihn alle 5 Minuten
aus. Der mitgelieferte Vercel-Schedule wird täglich ausgeführt, da der
Hobby-Plan nur tägliche Schedules zulässt. Konfigurieren Sie einen häufig
auszuführenden, authentifizierten Scheduler, wenn eine gehostete Bereitstellung
eine umgehende Wiederherstellung durch Wiederholungsversuche erfordert.

Ciele erstellt eine Alert, wenn es auf eine Erwähnung nicht antworten kann.
Mögliche Ursachen sind ein Kanal, dem Ciele nicht beigetreten ist, ein
archivierter oder freigegebener Kanal, ein unveröffentlichter Assistant sowie
eine fehlgeschlagene Zustellung. Wenn die Slack-Zustellung ein unsicheres
Ergebnis hat, unterdrückt Ciele automatische Reposts und erstellt einen Alert.
Überprüfen Sie den Slack-Thread, bevor Sie einen betroffenen Event manuell
erneut versuchen. Wenn das Slack-Token widerrufen wird oder abläuft, markiert
Ciele die Connection für eine erneute Verbindung. Die Liste Applications zeigt
dann **Reconnect** an.

## Erneut verbinden oder löschen

Wählen Sie **Reconnect**, wenn die Einwilligung abläuft oder sich das Konto
ändert. Die Verbindung behält dieselbe Identität, und ihre Imports bleiben
konfiguriert.

Wenn Sie einen Import löschen, werden dessen synchronisierte Sources für jeden
verknüpften Assistant gelöscht. Wenn Sie eine Connection löschen, werden alle
zugehörigen Imports und Sources gelöscht. Die Bestätigung zeigt die Anzahl der
betroffenen Imports, Sources und Assistant-Links an. Ciele versucht, den
Provider-Token zu widerrufen, wenn der Provider dies unterstützt, und entfernt
anschließend stets die lokalen Anmeldeinformationen.

## OAuth für eine Self-Hosted-Bereitstellung konfigurieren

Legen Sie `APP_ENCRYPTION_KEY` fest, bevor Sie einen Provider verbinden. Ciele
versiegelt OAuth-Token sowie die verbindungsspezifischen Salesforce- und
ServiceNow-Client-Secrets mit diesem Schlüssel.

Der Managed Service von Ciele stellt die gemeinsam genutzten
OAuth-Registrierungen für Slack, Microsoft und Google bereit. Jede
Self-Hosted-Bereitstellung stellt ihre eigenen Registrierungen über
Umgebungsvariablen bereit. Diese Registrierungen identifizieren die
Ciele-Bereitstellung. Sie identifizieren kein Organization- oder Member-Konto.

Erstellen Sie OAuth-Anwendungen des Providers und legen Sie die Paare fest, die
Sie aktivieren:

```dotenv
SLACK_APPLICATION_CLIENT_ID=
SLACK_APPLICATION_CLIENT_SECRET=
MICROSOFT_APPLICATION_CLIENT_ID=
MICROSOFT_APPLICATION_CLIENT_SECRET=
GOOGLE_APPLICATION_CLIENT_ID=
GOOGLE_APPLICATION_CLIENT_SECRET=
APPLICATION_IMPORT_MAX_REMOTE_ITEMS=100000
APPLICATION_IMPORT_MAX_ORG_BYTES=5368709120
APPLICATION_IMPORT_MAX_CONCURRENT=3
```

Die drei Limits betreffen synchronisierte Remote-Elemente pro Connection,
gespeicherte Application-Bytes pro Organization sowie aktive Sync-Claims pro
Organization. Senken Sie diese Werte für kleinere Bereitstellungen. Ciele führt
Checkpoints für den Provider-Cursor durch und setzt große Importe in späteren
Durable Claims fort.

Salesforce- und ServiceNow-Client-Anmeldeinformationen sind spezifisch für die
verbundene Organisation. Der Administrator gibt sie im geschützten Formular
Connection ein. Ciele versiegelt sie vor der Speicherung und gibt sie niemals an
den Browser zurück. ServiceNow verwendet den Authorization Code und speichert
weder einen Benutzernamen noch ein Passwort.

Registrieren Sie genau eine Callback-URL pro Provider. Ersetzen Sie `{origin}`
durch den öffentlichen HTTPS-Ursprung Ihrer Ciele-Konsole:

| Provider | Callback URL |
| --- | --- |
| Salesforce | `{origin}/api/applications/oauth/salesforce/callback` |
| ServiceNow | `{origin}/api/applications/oauth/servicenow/callback` |
| Slack | `{origin}/api/applications/oauth/slack/callback` |
| OneDrive | `{origin}/api/applications/oauth/onedrive/callback` |
| Google Drive | `{origin}/api/applications/oauth/google_drive/callback` |

Ein fehlendes Paar von Umgebungsvariablen für Slack, Microsoft oder Google
verhindert die Autorisierung für den jeweiligen Anbieter. **Connect** öffnet
weiterhin die Ciele-Verbindungsseite, auf der erläutert wird, dass die
Bereitstellung eingerichtet werden muss. Admins und Owners können den
Setup-Leitfaden von dieser Seite aus öffnen. Salesforce und ServiceNow bleiben
verfügbar, da der Admin seine OAuth-Registrierung im Connection-Formular
eingibt. Beide verwenden den Authorization Code. Salesforce, Microsoft und
Google verwenden ebenfalls PKCE. Jede Transaktion ist kurzlebig und an die
Organization, das initiierende Member, den Provider sowie die exakte
Callback-URL gebunden.

## Fehlerbehebung

| Symptom | Aktion |
| --- | --- |
| Auf der Verbindungsseite wird angezeigt, dass der Provider aktiviert werden muss | Konfigurieren Sie die Deployment Client ID und das Secret dieses Providers sowie `APP_ENCRYPTION_KEY` und starten Sie anschließend den Webdienst neu. |
| Salesforce oder ServiceNow lehnt den Client ab | Überprüfen Sie die Client ID, das Client Secret, die Instance URL und den exakten Callback in der Provider-Anwendung dieser Organisation. |
| Der Provider lehnt den Callback ab | Stellen Sie sicher, dass der registrierte Callback exakt mit dem öffentlichen Ciele-Origin und dem Pfad übereinstimmt. |
| Die Verbindung meldet, dass eine Autorisierung erforderlich ist | Wählen Sie **Reconnect** aus und genehmigen Sie die angeforderten Leseberechtigungen erneut. |
| Ein Ordner oder ein Kanal fehlt | Stellen Sie sicher, dass das autorisierte Konto ihn öffnen kann und – im Falle von Slack – Mitglied des Kanals ist. |
| Elemente werden übersprungen | Öffnen Sie das letzte Synchronisierungsergebnis. Überprüfen Sie, ob der Grund ein nicht unterstützter Typ, leerer Inhalt oder der Provider-Bereich ist. |
| Importierter Inhalt antwortet nicht | Stellen Sie sicher, dass die Source **Ready** ist und dass der Import mit dem erwarteten Assistant verknüpft ist. |

Anwendungsimporte sind für Quellinhalte schreibgeschützt, und das Token einer
Importverbindung kann keine Beiträge erstellen. Nur eine Verbindung mit
vollständigen Berechtigungen für Konversationen kann Slack-Antworten posten.
Ciele erzwingt zum Zeitpunkt der Beantwortung keine Zugriffskontrolllisten von
Anbietern und unterstützt keine SharePoint-Bibliotheken.
