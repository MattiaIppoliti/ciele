---
title: Entitäten und Datensätze
description: Definieren Sie typisierte Organisationsdaten, importieren Sie CSV-Zeilen und stellen Sie Tools für den sicheren Abruf bereit.
---

Eine Entity beschreibt eine Art von strukturierten Organisationsdaten. Ihre
Records enthalten die Werte, die ein Assistant abfragen kann.

Eine **Orders** Entity kann die Attribute `order_id`, `status`, `total` und
`customer_email` enthalten.

## Eine Entität erstellen

1. Gehen Sie in der Konsole zu `/settings/data`. Die Registerkarten **Settings**
   zeigen diese Seite nicht an.
2. Wählen Sie **New entity** aus.
3. Geben Sie einen Namen und eine Beschreibung ein.
4. Fügen Sie jeden Attributschlüssel, jedes Label und jeden Typ hinzu.
5. Wählen Sie das Schlüsselattribut aus.
6. Wählen Sie **Shared** oder **User-scoped** aus.
7. Wählen Sie **Create entity** aus.

Attribute unterstützen Text-, Zahlen-, Datums- und Boolesche Werte. Das
Schlüsselattribut identifiziert einen Datensatz innerhalb der Entität.

Die Attribute, der Schlüssel und der Scope einer Entity werden nach der
Erstellung festgeschrieben. Erstellen Sie eine weitere Entity, wenn sich diese
Struktur ändern muss.

## Eine Entität bearbeiten oder löschen

Öffnen Sie eine Entity und wählen Sie **Edit**, um ihren Namen oder ihre
Beschreibung zu ändern. Seine Attribute, sein Key-Attribut und sein Scope
bleiben unveränderlich.

Wählen Sie **Delete**, um die Entity und alle zugehörigen Records zu entfernen.

## Wählen Sie den Scope aus

| Scope | Verwenden Sie es für | Laufzeitverhalten |
| --- | --- | --- |
| **Shared** | Kataloge, Zeitpläne, Standorte und allgemeine Referenzdaten | Jeder vom Assistenten bediente Visitor kann passende Records abfragen. |
| **User-scoped** | Orders, Accounts, Applications und andere besucherbezogene Daten | Der Server schränkt jede Abfrage auf den verifizierten, angemeldeten Visitor ein. |

Eine Entity mit Benutzerumfang benötigt ebenfalls ein Identitätsattribut. Seine
Werte müssen mit dem konfigurierten
[Entra identity claim](/authentication/microsoft-entra-id#choose-an-identity-claim)
übereinstimmen.

## Datensätze aus CSV importieren

1. Öffnen Sie die Entity.
2. Wählen Sie **Import CSV** aus.
3. Wählen Sie eine CSV-Datei aus oder fügen Sie deren Text ein.
4. Stellen Sie sicher, dass jede Kopfzeile mit einem Attributschlüssel oder
   -label übereinstimmt. Bei der Übereinstimmungsprüfung wird die Groß- und
   Kleinschreibung nicht berücksichtigt.
5. Wählen Sie **Import** aus.
6. Überprüfen Sie die Anzahl der importierten und der abgelehnten Zeilen.

Importe führen ein Upsert anhand des Schlüsselattributs durch. Wenn Sie
denselben Schlüssel erneut importieren, wird sein Record aktualisiert, anstatt
ein Duplikat zu erstellen.

Gültige Zeilen werden weiterhin importiert, auch wenn andere Zeilen die
Validierung nicht bestehen. Der Bericht führt für jede abgelehnte Zeile einen
Grund auf.

Eine unbekannte CSV-Spalte führt dazu, dass der Import abgelehnt wird. Entfernen
Sie sie, oder fügen Sie das entsprechende Attribut zu einer neuen Entity hinzu.

## Datensätze von einem Endpunkt synchronisieren

Eine Entity kann ihre Records auch nach einem festgelegten Zeitplan von Ihrem
eigenen JSON-Endpoint lesen.

1. Öffnen Sie die Entity und wählen Sie **Sync**.
2. Geben Sie das **Endpoint URL** ein.
3. Geben Sie die Authentifizierungs-Header ein, jeweils ein `name: value`-Paar
   pro Zeile.
4. Ordnen Sie jedes JSON-Feld einem Attribut zu, ein
   `jsonField -> attributeKey`-Paar pro Zeile.
5. Geben Sie das Intervall in Stunden ein. Der Mindestwert beträgt 1 Stunde.
6. Wählen Sie **Remove records missing from the source**, wenn der Endpoint die
   vollständige Liste darstellt.
7. Speichern Sie, oder wählen Sie **Sync now**, um es sofort auszuführen.

Ciele verschlüsselt die Header vor der Speicherung. Eine Synchronisierung führt
Upserts anhand des Schlüsselattributs durch, genau wie ein CSV-Import.

Wählen Sie **Records**, um die ersten 50 Datensätze in der Reihenfolge der
Schlüssel zu durchsuchen.

## Eine Entität mit einem Assistenten verbinden

1. Öffnen Sie den Assistant.
2. Wählen Sie **Tools & Skills** aus.
3. Suchen Sie nach **Data**.
4. Wählen Sie jede Entität aus, die der Assistent abfragen darf.
5. Testen Sie die exakte Suche und die Textsuche in **Preview**.
6. Veröffentlichen Sie den Assistant.

Jede ausgewählte Entity kann ein Tool für die exakte Filterung bereitstellen.
Entities mit Textattributen stellen außerdem ein Tool zur Stichwortsuche bereit.

Die ausgewählten Entity-Schemas werden in den Publication-Snapshot übernommen.
Nicht ausgewählte Entitäten erzeugen keine Tools.

Der Inhalt der Datensätze wird live gelesen. Das Importieren aktualisierter
Records erfordert keine weitere Publication.

## Schutz von Records mit Benutzerumfang

Tools mit Benutzerumfang existieren nur, wenn der Turn eine verifizierte
Identitätsangabe enthält. Anonyme Besucher erhalten diese Tools nicht.

Das Attribut `identity` wird aus der modellseitigen Tool-Eingabe entfernt. Der
Server fügt jeder Abfrage den verifizierten Wert hinzu.

Wenn der Claim fehlt, bleiben die Tools mit Benutzerumfang nicht verfügbar.
Shared Entity-Tools können weiterhin funktionieren.

<Callout title="Identity cannot come from the prompt">
Never ask a Visitor to type the identity used for Record access. Configure the claim in Microsoft Entra ID instead.
</Callout>
