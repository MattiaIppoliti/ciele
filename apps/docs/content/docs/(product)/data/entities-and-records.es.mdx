---
title: Entidades y registros
description: Define datos tipados de la organización, importa filas CSV y proporciona herramientas de recuperación seguras.
---

Una Entity describe un tipo de datos estructurados de la organización. Sus
Records contienen los valores que un Assistant puede consultar.

Una entidad **Orders** puede contener los atributos `order_id`, `status`,
`total` y `customer_email`.

## Crea una entidad

1. Ve a `/settings/data` en la consola. Las pestañas **Settings** no muestran
   esta página.
2. Selecciona **New entity**.
3. Introduce un nombre y una descripción.
4. Añade cada clave, etiqueta y tipo de atributo.
5. Selecciona el atributo key.
6. Selecciona **Shared** o **User-scoped**.
7. Selecciona **Create entity**.

Los atributos admiten valores de tipo texto, número, fecha y booleano. El
atributo key identifica un registro dentro de la entidad.

Los atributos, la clave y el ámbito de una entidad quedan fijados tras su
creación. Crea otra entidad cuando sea necesario modificar esa estructura.

## Editar o eliminar una entidad

Abre una Entity y selecciona **Edit** para cambiar su nombre o su descripción.
Sus atributos, su atributo clave y su ámbito permanecen fijos.

Selecciona **Delete** para eliminar la entidad y todos sus registros.

## Elige el ámbito

| Ámbito | Úsalo para | Comportamiento en tiempo de ejecución |
| --- | --- | --- |
| **Shared** | Catálogos, horarios, ubicaciones y datos de referencia comunes | Cualquier Visitor atendido por el Assistant puede consultar los Records coincidentes. |
| **User-scoped** | Pedidos, cuentas, aplicaciones y otros datos específicos de cada Visitor | El servidor restringe todas las consultas al Visitor verificado que ha iniciado sesión. |

Una Entidad con ámbito de usuario también necesita un atributo de identidad. Sus
valores deben coincidir con la
[Entra identity claim](/authentication/microsoft-entra-id#choose-an-identity-claim)
configurada.

## Importa registros desde un archivo CSV

1. Abre la entidad.
2. Selecciona **Import CSV**.
3. Elige un archivo CSV o pega su texto.
4. Confirma que cada encabezado coincida con una clave de atributo o una
   etiqueta. La coincidencia no distingue entre mayúsculas y minúsculas.
5. Selecciona **Import**.
6. Revisa los recuentos de filas importadas y rechazadas.

Las importaciones realizan una operación upsert según el atributo clave. Al
volver a importar la misma clave, se actualiza su registro en lugar de crear un
duplicado.

Las filas válidas se siguen importando aunque otras filas no superen la
validación. El informe indica un motivo para cada fila rechazada.

Una columna CSV desconocida rechaza la importación. Elimínala o añade el
atributo correspondiente a una nueva Entity.

## Sincronizar registros desde un endpoint

Una Entity también puede leer sus Records desde tu propio endpoint JSON según
una programación.

1. Abre la entidad y selecciona **Sync**.
2. Introduce el **Endpoint URL**.
3. Introduce los encabezados de autenticación, un par `name: value` en cada
   línea.
4. Asigna cada campo JSON a un atributo, un par `jsonField -> attributeKey` en
   cada línea.
5. Introduce el intervalo en horas. El mínimo es 1 hora.
6. Selecciona **Remove records missing from the source** si el endpoint es la
   lista completa.
7. Guarda o selecciona **Sync now** para ejecutarlo inmediatamente.

Ciele cifra los encabezados antes de almacenarlos. Una sincronización realiza
upserts por el atributo key, igual que una importación CSV.

Selecciona **Records** para explorar los primeros 50 registros ordenados por
clave.

## Conecta una entidad a un asistente

1. Abre el Assistant.
2. Selecciona **Tools & Skills**.
3. Busca **Data**.
4. Selecciona cada Entidad a la que el Asistente pueda realizar consultas.
5. Prueba la búsqueda exacta y la búsqueda de texto en **Preview**.
6. Publica el asistente.

Cada Entity seleccionada puede ofrecer una herramienta de filtrado exacto. Las
entidades con atributos de texto también ofrecen una herramienta de búsqueda por
palabras clave.

Los esquemas de las Entidades seleccionadas pasan a formar parte de la
instantánea de Publicación. Las Entities no seleccionadas no generan ninguna
herramienta.

El contenido de los registros se lee en tiempo real. Importar Registros
actualizados no requiere otra Publicación.

## Protege los Registros con ámbito de usuario

Las herramientas con ámbito de usuario solo existen cuando el turno contiene una
declaración de identidad verificada. Los visitantes anónimos no reciben esas
herramientas.

Se elimina el atributo identity de la entrada de la herramienta orientada al
modelo. El servidor añade el valor verificado a cada consulta.

Si falta la afirmación, las herramientas con ámbito de usuario siguen estando no
disponibles. Las herramientas de Shared Entity pueden seguir funcionando.

<Callout title="Identity cannot come from the prompt">
Never ask a Visitor to type the identity used for Record access. Configure the claim in Microsoft Entra ID instead.
</Callout>
