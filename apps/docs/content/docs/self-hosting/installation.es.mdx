## Requisitos

- Instala Git.
- Instala Docker con Docker Compose.
- Reserva suficiente espacio en disco para las imágenes, Postgres y los archivos
  subidos.
- Reserva más memoria cuando habilites los trabajadores opcionales.

## Un comando

El instalador realiza todos los pasos de la siguiente sección: verifica los
requisitos previos, descarga el código fuente en `./ciele` y ejecuta
`bootstrap.sh`.

```bash
curl -fsSL https://ciele.app/install.sh | sh
```

Pasa los indicadores de Bootstrap a través de la canalización con `-s --` y
configura `CIELE_DIR` para elegir el directorio de descarga o `CIELE_REF` para
instalar una etiqueta de versión:

```bash
curl -fsSL https://ciele.app/install.sh | sh -s -- --seed
```

El instalador nunca elimina nada: si el directorio de destino existe y no es una
copia de Ciele, se detiene y te lo indica.

En un Mac sin Docker, el instalador no se detiene ante un error. Abre
[Ciele Desktop](/self-hosting/desktop) y, si la aplicación no está presente,
primero descarga la versión. La configuración guiada que aparece allí vincula
Docker Desktop e inicia la misma pila que se describe en esta página. En Linux,
el instalador se niega porque no hay ninguna aplicación de escritorio a la que
pasarle el trabajo.

## Arranca la pila

Para realizar los mismos pasos manualmente:

```bash
git clone https://github.com/MattiaIppoliti/ciele.git
cd ciele
./deploy/bootstrap.sh
```

El script genera los secretos necesarios en `deploy/.env`. A continuación,
compila e inicia los perfiles predeterminados.

Abre [http://localhost:3000](http://localhost:3000) cuando los servicios estén
en buen estado. La primera cuenta se convierte en la propietaria de la
organización.

Utiliza `./deploy/bootstrap.sh --seed` para añadir contenido de demostración
depurado.

## Ejecuta imágenes publicadas en lugar de compilar

Compilar `app`, `migrate` y `cron` desde el «checkout» lleva bastante tiempo y
requiere el repositorio completo. Cada versión también publica esas tres como
imágenes de contenedor:

```bash
./deploy/bootstrap.sh --images v0.4.0
```

El comando escribe dos configuraciones en `deploy/.env` y extrae en lugar de
compilar:

```bash
COMPOSE_FILE=docker-compose.yml:docker-compose.images.yml
CIELE_IMAGE_TAG=v0.4.0
```

Dado que ambos se encuentran en `deploy/.env`, un `docker compose up -d`
posterior en ese directorio permanece en modo de imagen. Borra ambos ajustes
para volver a compilar desde el código fuente. Configura `CIELE_IMAGE_REGISTRY`
para que use una réplica o tu propia recompilación.

Los perfiles, el orden de los servicios y la capa de base de datos son idénticos
en ambos modos. Solo cambia el origen de esos tres servicios.

<Callout title="Recreate the container after changing the public URL">
The published application image resolves `SUPABASE_PUBLIC_URL` once, when the
container starts, because Next.js inlines that class of value at build time.
Run `docker compose up -d` to recreate the container after you change it. A
restart alone keeps the previous value.
</Callout>

## Perfiles predeterminados

| Perfil | Predeterminado | Servicios |
| --- | :---: | --- |
| `db` | Sí | Postgres, pgvector, autenticación, API de datos, almacenamiento y puerta de enlace. |
| `migrate` | Sí | Migraciones pendientes y buckets de almacenamiento necesarios. |
| `app` | Sí | Consola de administrador, entorno de ejecución de widgets y API v1. |
| `cron` | Sí | Tareas programadas de la aplicación. |
| `workers` | No | Servicios de recuperación de grafos y de rastreo con renderización en JavaScript. |
| `studio` | No | Interfaz de administración de la base de datos. |

## Inspecciona la pila

```bash
docker compose -f deploy/docker-compose.yml ps
docker compose -f deploy/docker-compose.yml logs -f app
```

La configuración predeterminada publica la aplicación en el puerto `3000` y la
puerta de enlace de la base de datos en el puerto `8000`. No publica Postgres.

<Callout type="warn" title="Add TLS before public use">
The Compose stack serves plain HTTP. Put a trusted reverse proxy in front of every public origin.
</Callout>
