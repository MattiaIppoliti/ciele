Ciele viene pubblicato come release con tag. Ogni release è un singolo commit
sul repository pubblico più un tag `vMAJOR.MINOR.PATCH`, quindi la domanda
"quale versione sto usando" ha sempre una risposta precisa:

```sh
git describe --tags
```

Fissa la tua distribuzione a un tag invece di seguire il ramo predefinito, e
decidi tu quando spostarla.

## Aggiorna una distribuzione Docker

```sh
git fetch --tags
git checkout v0.2.0        # the release you want
docker compose -f deploy/docker-compose.yml up -d --build
```

Questo ricostruisce l'immagine dell'app e riavvia lo stack. Il servizio
`migrate` viene eseguito per primo, applica solo le migrazioni che non hai già e
termina; l'app si avvia una volta terminato. Non esegui le migrazioni
manualmente.

Se hai abilitato il [profilo workers](/self-hosting/workers), `--build`
ricostruisce anche quelle immagini, senza alcun passaggio separato.

## Aggiorna una distribuzione sorgente

Esecuzione diretta delle app anziché in Compose:

```sh
git fetch --tags && git checkout v0.2.0
pnpm install
pnpm build
```

Applica le migrazioni in sospeso al tuo database prima di avviare la nuova
build. Consulta [Database](/self-hosting/database) per capire come funziona il
runner ordinato per nome di file e come tiene traccia di ciò che ha già
applicato.

## Esegui prima il backup

Un aggiornamento che applica le migrazioni modifica il tuo schema. Esegui sempre
un dump prima di iniziare:

```sh
docker compose -f deploy/docker-compose.yml exec -T postgres \
  pg_dump -U postgres postgres | gzip > ciele-$(date +%F).sql.gz
```

Due volumi contengono tutto ciò che conta: `postgres-data` (il database) e
`storage-data` (i file caricati). Esegui il backup di entrambi: un semplice dump
del database ripristinerà i tuoi assistenti, le conversazioni e i record di
conoscenza, ma non i file sottostanti.

<Callout type="warn" title="Migrations move forward only">
There is no down-migration path. Rolling back to an earlier version means
restoring the backup you took before the upgrade, not re-running the runner in
reverse. This is why the dump above is not optional.
</Callout>

## Ripristino

```sh
docker compose -f deploy/docker-compose.yml down
git checkout v0.1.0
gunzip -c ciele-2026-07-25.sql.gz | docker compose -f deploy/docker-compose.yml \
  exec -T postgres psql -U postgres postgres
docker compose -f deploy/docker-compose.yml up -d --build
```

Ripristina il dump corrispondente alla versione a cui stai tornando. Un dump più
recente contiene uno schema più recente, che il codice precedente non
riconoscerà.

## Cosa leggere prima di un aggiornamento minore

Le note di rilascio vengono pubblicate su ogni tag e segnalano tutto ciò che
richiede una tua decisione: una nuova variabile di ambiente obbligatoria, un
valore predefinito modificato, una migrazione che riscrive una tabella di grandi
dimensioni. Dai una rapida occhiata prima di aggiornare una distribuzione da cui
dipendono altre persone; le versioni patch sono di routine, le versioni minori a
volte non lo sono.
