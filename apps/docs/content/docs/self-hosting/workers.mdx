---
title: Background workers
description: Enable optional graph retrieval and JavaScript-rendering crawl services.
---

The default stack does not start the `workers` profile. Search and website ingestion continue with reduced capabilities.

Without the graph worker, Knowledge uses vector and lexical retrieval. Without Crawl4AI, Ciele uses its built-in fetch crawler.

## Enable the profile

Set these values in `deploy/.env`:

```dotenv
COMPOSE_PROFILES=db,migrate,app,cron,workers
GRAPH_WORKER_API_TOKEN=<generated-token>
GRAPH_LLM_API_KEY=<provider-key>
CRAWL4AI_API_TOKEN=<generated-token>
CRAWL4AI_SECRET_KEY=<generated-token>
```

Then start the stack:

```bash
docker compose -f deploy/docker-compose.yml up -d
```

The two optional workers can require approximately 8 GiB of memory. Measure the actual use on your selected host.

## Check worker status

```bash
docker compose -f deploy/docker-compose.yml ps
docker compose -f deploy/docker-compose.yml logs -f graph-worker crawl4ai
```

Do not expose worker ports or tokens to the public network.

## Long-term memory jobs

Long-term memory uses the built-in durable job ledger. It does not require the optional `workers` profile.

Each signed-in turn schedules a `promote_memories` job after a 15-minute quiet window. The `cron` profile drains these jobs through the existing scheduled route.

Keep `cron` in `COMPOSE_PROFILES` when long-term memory is enabled. The default self-host configuration already includes it.

The job skips extraction when memory is disabled or the daily token budget is exhausted. It also skips when no suitable model connection exists.
