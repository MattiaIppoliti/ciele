[Wissen](/knowledge) gelangt als **Quelle** in das System, wird zu **Konzepte**
angereichert und als eingebettete **Chunks** gespeichert. Der Abruf durchläuft
diese Kette in umgekehrter Richtung, wodurch eine Antwort auf eine benannte
Quelle verweisen kann, anstatt auf ein undurchsichtiges Textfragment.

## Von einer Quelle zu durchsuchbarem Text

Nichts in dieser Pipeline wird auf der Anfrage ausgeführt, die sie gestartet
hat. Das Hinzufügen einer Quelle zeichnet diese auf und stellt einen Auftrag in
die Warteschlange. Die Pipeline leert anschließend diese Warteschlange, und die
Konsole fragt währenddessen den Status der Quelle ab.

<Mermaid
  title="Aufnahme: Aus einer Quelle werden viele eingebettete Chunks"
  chart={`
flowchart TB
  IN["A member adds a source<br/>text · file · link · website"]
  ROW["Create the source row<br/>status: processing"]
  Q["Queue an ingestion job"]
  EX{"Extractor,<br/>by source kind"}
  T["text"]
  U["link"]
  F["file"]
  W["website"]
  OKF["Enrich into concepts<br/>markdown + front matter"]
  CH["Split into chunks"]
  EM["Embed each chunk"]
  PERSIST["One write path<br/>create concept + index it"]
  DB[("concepts + concept_chunks<br/>with a vector index")]
  DONE["status: ready"]
  ERR["status: error<br/>+ reason"]

  IN --> ROW --> Q
  Q -->|"off the request path"| EX
  EX --> T & U & F & W --> OKF
  OKF --> CH --> EM --> PERSIST --> DB --> DONE
  Q -.->|"failure anywhere"| ERR
`}
/>

Hier erledigen zwei Nahtstellen die Arbeit, und beide sind Register und keine
Bedingungsanweisungen:

- **Extraction** ist ein Extractor pro Quellentyp. Das Hinzufügen eines neuen
  Quellentyps bedeutet, einen Extractor hinzuzufügen, und nicht die Bearbeitung
  eines Parsers, der bereits vier andere Formate verarbeitet.
- **Persistence** ist ein einziger Schreibpfad. Jeder Pfad, der Wissen liefert –
  eine angereicherte Quelle, eine gecrawlte Seite, eine handgeschriebene FAQ –
  durchläuft dieselbe Funktion, die das Konzept erstellt und indiziert. Es gibt
  keine zweite Möglichkeit, ein Konzept zu schreiben. Deshalb kann das System
  keinen Chunk ohne Index erreichen.

Ein Konzept kann von der Abfrage ausgeschlossen werden, ohne gelöscht zu werden.
Dies ist der Mechanismus, mit dem Sie eine gecrawlte Seite ausblenden, von der
Sie keine Antworten erhalten möchten.

## Durchforsten einer Website

Webseiten-Quellen sind die einzige Art mit echter operativer Vielfalt, sodass
der Crawler eine Anbieter-Matrix hinter einem einzigen Lebenszyklus ist. Eine
Quelle wählt einen Provider aus – oder überlässt dies der Automatisierung. In
letzterem Fall löst eine reine Capability-Richtlinie zu Beginn des Crawls einen
Provider und zeichnet auf, welchen sie ausgewählt hat.

<Mermaid
  title="Crawler-Auswahl und die Sicherheitsprüfungen, die jeder Anbieter besteht"
  chart={`
flowchart TB
  SRC["Website source<br/>provider: automatic | local | rendered | managed"]
  POL{"Automatic?"}
  CAP["Capability policy<br/>needs a browser? files?<br/>a login? a proxy?"]
  PICK["Resolve one provider<br/>and persist the choice"]

  GUARD["Target validation<br/>HTTP(S) only · no credentials in the URL<br/>no loopback, private, link-local, or metadata address<br/>reject hosts that resolve privately"]

  L["Local crawler<br/>in-process, same origin"]
  R["Rendered crawler<br/>browser worker"]
  M["Managed crawler<br/>external service"]

  PAGES["One concept per page"]

  SRC --> POL
  POL -->|"yes"| CAP --> PICK
  POL -->|"no"| PICK
  PICK --> GUARD
  GUARD --> L & R & M
  L & R & M --> PAGES
`}
/>

Jeder Anbieter durchläuft dieselbe Validierung, bevor ein Ziel übermittelt wird.
Der lokale Crawler validiert zusätzlich jede Weiterleitung erneut, bleibt auf
dem Start-Ursprung, bindet seine Verbindungen an die Adresse, die die
Validierung bestanden hat, begrenzt die Antwortgröße und erzwingt sowohl
pro-Seite- als auch Gesamt-Deadlines.

<Callout title="Where the boundary actually is">
The remote providers receive an already-validated hostname and resolve it inside
their own network. Address pinning for those crawls is therefore outside this
process's control — worth knowing if your threat model cares. Worker credentials
are server-only and are stripped from any error, alert, or telemetry a member can
see.
</Callout>

Beim erneuten Crawlen werden die vorherigen Seiten ersetzt, anstatt sie zu
ergänzen. Eine Seite, die von einer Website verschwindet, wird also nicht mehr
beantwortet.

## Einbettungen

Jeder Chunk wird in einer Vektorspalte mit einem Index und einer festen Breite
gespeichert. Ein Anbieter, dessen Vektoren kürzer sind, wird auf diese Breite
mit Nullen aufgefüllt – die Kosinus-Ähnlichkeit wird durch das Auffüllen nicht
beeinflusst, sodass ein einziger Index für jeden Anbieter ausreicht.

<Mermaid
  title="Präferenz für den Embedding-Anbieter und der Fallback, wenn es keinen gibt"
  chart={`
flowchart TB
  CH["A chunk of text"]
  RES{"Which provider<br/>can embed?"}
  O["OpenAI"]
  G["Google"]
  N["None configured"]
  PAD["Pad to the fixed width"]
  VEC[("Vector column<br/>one shared index")]
  LEX["Lexical search<br/>no vector stored"]

  CH --> RES
  RES --> O --> PAD
  RES --> G --> PAD
  RES --> N --> LEX
  PAD --> VEC
`}
/>

Das Auffüllen ist ein bewusster Kompromiss: ein gemeinsamer Index und keine
Migration bei einem Anbieterwechsel, allerdings mit dem Nachteil, dass beim
Vergleich von Vektoren, die von verschiedenen Modellen erzeugt wurden, Vorsicht
geboten ist. Wenn überhaupt kein Embedding-Anbieter konfiguriert ist, wird die
Abfrage auf eine lexikalische Suche reduziert, anstatt fehlzuschlagen – nach
demselben Prinzip wie beim Keyword-Router in der
[Chat-Runtime](/self-hosting/architecture/chat-runtime).

Eine Organisation kann auch festlegen, welche Provider-Verbindung die Einbettung
vornimmt, unabhängig davon, welcher Provider den Chat beantwortet.

## Abruf und Zitate

Die Abfrage ist eine Ähnlichkeitssuche über Chunks, die auf den Assistenten und
die ausgewählte Sammlung beschränkt ist und durch lexikalische Übereinstimmungen
ergänzt wird, wenn die Vektorergebnisse spärlich sind. Ausgeschlossene Konzepte
werden in SQL gefiltert und nicht erst im Nachhinein.

<Mermaid
  title="Von einer Abfrage zu einem Zitatchip"
  chart={`
flowchart TB
  Q["Query"] --> EMB["Embed the query"]
  EMB --> MATCH["Similarity search<br/>scoped by assistant + collection"]
  MATCH --> TOPUP["Top up with lexical matches"]
  TOPUP --> RESOLVE["Resolve chunk → concept → source"]
  RESOLVE --> ANSWER["Grounded answer"]
  RESOLVE --> CITE["Citation chips<br/>named sources"]
`}
/>

Der Auflösungsschritt ist der entscheidende Schritt. Die Ergebnisse werden
niemals als bloße Fragmente an das Modell – oder an den Leser – übergeben; jedes
Ergebnis trägt das Konzept, aus dem es stammt, und die Quelle, aus der dieses
Konzept erstellt wurde. Deshalb wird dieselbe Zitierkomponente im Widget, in der
Vorschau der Konsole und im Transkript des [Posteingangs](/operations/inbox)
gerendert: Es gibt nur eine Form, die gerendert werden muss, da Zitierungen
immer auf dasselbe Objekt aufgelöst werden.
