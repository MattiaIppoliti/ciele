## Anwendungen

| Pfad | Zuständigkeit |
| --- | --- |
| `apps/web` | Administrator Console, Widget Runtime, Public Pages, Server Actions und API v1. |
| `apps/docs` | Fumadocs-Dokumentationsanwendung und Übersetzungspipeline. |

## Gemeinsam genutzte Pakete

| Path | Verantwortlichkeit |
| --- | --- |
| `packages/core` | Domain-Typen, reine Flow-Regeln, Standardwerte, Bedingungen und Analytiklogik. |
| `packages/db` | Persistenzschnittstellen, Mock-Speicher und Supabase-Implementierung. |
| `packages/agent` | Ausführung von Turns, Modellanbieter, Knowledge-Tools, Ingestion und Evaluation. |
| `packages/ops` | Von Console-Aktionen und API v1 verwendete gemeinsame Organisation-Operationen. |
| `packages/client` | Typed client für API v1. |
| `packages/cli` | Terminal-Schnittstelle über den Typed Client. |
| `packages/mcp` | Lokaler MCP-Adapter mit vierzehn Tools über den Typed Client. |
| `packages/ui` | Gemeinsam genutzte Komponenten der Benutzeroberfläche. |
| `packages/charts` | Gemeinsam genutzte Analytics-Visualisierungen. |

## Services und Infrastruktur

| Path | Zuständigkeit |
| --- | --- |
| `services/crawl4ai` | Optionale Konfiguration des Crawlers für das JavaScript-Rendering. |
| `supabase/migrations` | Geordnete Änderungen am Datenbankschema. |
| `deploy` | Single-Host-Docker-Compose-Bereitstellung und Bootstrap-Skripte. |

## Richtung der Abhängigkeiten

Pure Rules gehören in `packages/core`. Das Persistenzverhalten gehört in
`packages/db`.

Wiederverwendbare Mutationen gehören in `packages/ops`. Das Modell- und
Abrufverhalten gehört in `packages/agent`.

Surface-Adapter in `apps/web`, `packages/cli` und `packages/mcp` dürfen kein
separates Domain-Verhalten erzeugen.
