## Proprietà del tenant

Un'Organization è il tenant principale. I membri si uniscono a un'Organization
con un solo Role.

I record di proprietà dell'organizzazione includono Assistants, Teammates,
Entities, Memories, Help Desks, connessioni ai provider, API keys, Skills,
Improvements, Goals, Alerts e record di utilizzo.

I record dei Teammate includono Projects, documenti di memoria, Routines e
thread di gruppo. Un group thread conserva i propri messaggi, non le
Conversations.

## Configurazione dell'Assistente

<Mermaid
  title="Un Assistant possiede il proprio routing e i propri snapshot"
  chart={`

  ORG["Organization"]
  ASSISTANT["Assistant"]
  FLOW["Flow"]
  PUB["Publication"]
  ORG -->|"owns many"| ASSISTANT
  ASSISTANT -->|"routes with"| FLOW
  ASSISTANT -->|"snapshots into"| PUB
`}
/>

Una Publication memorizza uno snapshot immutabile della configurazione di un
Assistant. I record delle bozze rimangono modificabili anche dopo la
Publication.

Un Flow memorizza un trigger, la configurazione delle condizioni e le azioni
ordinate. La convalida in fase di runtime impone coppie valide di trigger e
azioni.

Un Assistant seleziona gli schemi delle Entity per la sua prossima Publication.
Lo snapshot dello schema controlla gli strumenti generati, mentre ogni query
legge i Record correnti.

Le Shared Entities espongono i dati comuni dell'Organization. Le Entità con
ambito utente indicano un attributo di identità per il filtraggio lato server.

## Proprietà della conoscenza

<Mermaid
  title="È un link, non una Collection, a decidere cosa cerca un Assistant"
  chart={`
flowchart TB
  ORG["Organization"]
  ASSISTANT["Assistant"]
  COLLECTION["Knowledge Collection"]
  SOURCE["Source"]
  DOCUMENT["Document"]
  ORG -->|"owns"| COLLECTION
  COLLECTION -->|"holds"| SOURCE
  SOURCE -->|"ingests into"| DOCUMENT
  ASSISTANT -->|"links to"| SOURCE
`}
/>

La Knowledge appartiene all'Organization. Una Collection è un contenitore, non
un proprietario, e non decide quale Assistente risponde da una Source.

È il collegamento Assistant-to-Source a farlo. Il modulo di Retrieval legge il
set di collegamenti, quindi una Source non collegata non risponde a nessuno. Il
collegamento prevede anche l'accesso diretto per ogni Assistente.

Eliminando un Assistente, i suoi collegamenti vengono rimossi e tutte le Source
restano al loro posto.

## Dati della conversazione

Una Conversation appartiene a un Assistant o a un Teammate, mai a entrambi. Una
Conversation dell'Assistente tiene traccia di una singola sessione del Visitor.

Una Teammate Conversation è una chat interna di un Member. Non viene
visualizzata in Inbox né in Insights. I messaggi memorizzano le parti digitate
per testo, citazioni, pulsanti, tracce e altre risposte.

Lo stato della sessione registra anche l'invio proattivo delle notifiche. Una
Notification non crea un messaggio Visitor.

Le Long-term Memories appartengono a una Organization e a un soggetto SSO
verificato. Memorizzano un fatto persistente, un embedding, i timestamp e la
provenienza della Conversation di origine.

Il runtime limita ogni soggetto a 200 memorie. L'eliminazione rimuove un fatto
dalle future iniezioni di prompt e dalle ricerche nella memoria.

## Credenziali programmatiche

Un record di chiave API appartiene a un'Organizzazione e memorizza un hash
segreto, un Role, il creator e lo stato di revoca. Il segreto in chiaro non
viene memorizzato.

## Isolamento

L'accesso autenticato alla console utilizza la sicurezza a livello di riga, ove
applicabile. I percorsi dei Service-role devono aggiungere un limite esplicito
all'Organization.

API v1 utilizza l'Organization risolta dalla chiave API. Non accetta come
autorità un'Organization selezionata dal chiamante.
