## Tenant-Eigentümerschaft

Eine Organization ist der primäre Tenant. Mitglieder treten einer Organization
mit einer Role bei.

Zu den der Organisation gehörenden Datensätzen zählen Assistants, Teammates,
Memories, Help Desks, Provider Connections, API Keys, Skills, Improvements,
Goals, Alerts sowie Nutzungsdatensätze.

Zu den Datensätzen von Teammates gehören Projects, Memory-Dokumente, Routines
und Group Threads. Ein Gruppen-Thread speichert seine eigenen Nachrichten, nicht
Conversations.

## Konfiguration des Assistenten

  title="Ein Assistant besitzt sein Routing und seine Snapshots"

  ORG -->|"owns many"| ASSISTANT
  ASSISTANT -->|"routes with"| FLOW
  ASSISTANT -->|"snapshots into"| PUB

/>

Eine Publication speichert einen unveränderlichen Snapshot der
Assistant-Konfiguration. Draft-Datensätze bleiben auch nach der Publication
bearbeitbar.

Ein Flow speichert einen Trigger, eine Bedingungskonfiguration und geordnete
Aktionen. Die Runtime-Validierung stellt sicher, dass nur gültige Paare aus
Trigger und Action verwendet werden.

## Eigentum an Wissen

<Mermaid
  title="Ein Link, nicht eine Collection, bestimmt, wonach ein Assistent sucht."
  chart={`
flowchart TB
  ORG["Organization"]
  ASSISTANT["Assistant"]
  COLLECTION["Knowledge Collection"]
  SOURCE["Source"]
  DOCUMENT["Document"]
  ORG -->|"owns"| COLLECTION
  COLLECTION -->|"holds"| SOURCE
  SOURCE -->|"ingests into"| DOCUMENT
  ASSISTANT -->|"links to"| SOURCE
`}
/>

Wissen gehört der Organisation. Eine Collection ist ein Container, kein
Eigentümer, und sie entscheidet nicht, welcher Assistant aus einer Source
antwortet.

Die Verknüpfung „Assistant-to-Source“ tut dies. Retrieval liest den Link-Satz
aus, sodass eine nicht verknüpfte Source niemandem antwortet. Die Verknüpfung
umfasst zudem den Direct-Zugriff pro Assistenten.

Wenn Sie einen Assistant löschen, werden dessen Verknüpfungen entfernt, während
alle Sources an ihrem Platz bleiben.

## Konversationsdaten

Eine Conversation gehört zu einem Assistant oder zu einem Teammate, niemals zu
beiden. Eine Assistant Conversation erfasst eine einzelne Visitor-Sitzung.

Eine Teammate Conversation ist ein interner Chat eines Members. Sie wird weder
in der Inbox noch in den Insights angezeigt. Messages speichern eingegebene
Teile für Text, Zitate, Buttons, Traces und andere Antworten.

Der Session-Status erfasst auch die proaktive Zustellung von Notifications. Eine
Notification erzeugt keine Visitor-Nachricht.

Long-term Memories gehören zu einer Organisation und einem verifizierten
SSO-Subject. Sie speichern eine dauerhafte Tatsache, eine Einbettung,
Zeitstempel und die Provenienz der Quell-Conversation.

Die Runtime begrenzt jedes Subject auf 200 Memories. Durch das Löschen wird eine
Tatsache aus zukünftigen Prompt-Injektionen und Memory-Suchen entfernt.

## Programmatische Anmeldeinformationen

Ein API-Schlüssel-Datensatz gehört zu einer Organisation und speichert einen
geheimen Hash, die Role, den Creator sowie den Revocation-Status. Das im
Klartext vorliegende Secret wird nicht gespeichert.

## Isolierung

Der authentifizierte Zugriff auf die Konsole verwendet gegebenenfalls
Row-Level-Security. Service-Rollenpfade müssen eine explizite
Organization-Grenze hinzufügen.

API v1 verwendet die anhand des API-Schlüssels aufgelöste Organization. Es
akzeptiert keine vom Aufrufer ausgewählte Organization als Autorität.
