## Tenant-Eigentümerschaft

Eine Organization ist der primäre Tenant. Mitglieder treten einer Organization
mit einer Role bei.

Zu den Datensätzen im Besitz der Organisation gehören Assistants, Teammates,
Entities, Memories, Help Desks, Provider Connections, API Keys, Skills,
Improvements, Goals, Alerts und Usage Records.

Zu den Teammate-Datensätzen gehören Projects, Memory-Dokumente, Routines und
Group-Threads. Ein Group Thread speichert seine eigenen Nachrichten, nicht
Conversations.

## Konfiguration des Assistenten

<Mermaid
  title="Ein Assistant ist Eigentümer seines Routings und seiner Snapshots"
  chart={`

  ORG["Organization"]
  ASSISTANT["Assistant"]
  FLOW["Flow"]
  PUB["Publication"]
  ORG -->|"owns many"| ASSISTANT
  ASSISTANT -->|"routes with"| FLOW
  ASSISTANT -->|"snapshots into"| PUB
`}
/>

Eine Publication speichert einen unveränderlichen Snapshot der
Assistant-Konfiguration. Draft-Datensätze bleiben auch nach der Publication
bearbeitbar.

Ein Flow speichert einen Trigger, eine Konfiguration der Bedingungen sowie
geordnete Actions. Die Laufzeitvalidierung stellt sicher, dass nur gültige Paare
aus Trigger und Aktion verwendet werden.

Ein Assistant wählt Entity-Schemas für seine nächste Publication aus. Der
Schema-Snapshot steuert die generierten Tools, während jede Abfrage die
aktuellen Records liest.

Shared Entities stellen gemeinsame Daten der Organisation bereit. User-scoped
Entities geben ein Identitätsattribut für die serverseitige Filterung an.

## Eigentum an Wissen

<Mermaid
  title="Ein Link, nicht eine Collection, bestimmt, wonach ein Assistant sucht."
  chart={`
flowchart TB
  ORG["Organization"]
  ASSISTANT["Assistant"]
  COLLECTION["Knowledge Collection"]
  SOURCE["Source"]
  DOCUMENT["Document"]
  ORG -->|"owns"| COLLECTION
  COLLECTION -->|"holds"| SOURCE
  SOURCE -->|"ingests into"| DOCUMENT
  ASSISTANT -->|"links to"| SOURCE
`}
/>

Wissen gehört der Organisation. Eine Collection ist ein Container, kein
Eigentümer, und sie entscheidet nicht, welcher Assistant aus einer Source
antwortet.

Die Verknüpfung „Assistant-to-Source“ bestimmt dies. Retrieval liest den
Link-Satz aus, sodass eine nicht verknüpfte Source niemandem antwortet. Die
Verknüpfung umfasst außerdem den Direct-Zugriff pro Assistenten.

Wenn Sie einen Assistant löschen, werden dessen Verknüpfungen entfernt, während
alle Sources unverändert bestehen bleiben.

## Konversationsdaten

Eine Conversation gehört zu einem Assistant oder zu einem Teammate, niemals zu
beiden. Eine Assistant Conversation verfolgt eine einzelne Visitor-Sitzung.

Eine Teammate Conversation ist ein interner Chat eines Members. Sie wird weder
in der Inbox noch in den Insights angezeigt. Messages speichern eingegebene
Elemente für Text, Zitate, Buttons, Traces und andere Antworten.

Der Session-Status erfasst auch die proaktive Zustellung von Notifications. Eine
Notification erzeugt keine Visitor-Nachricht.

Langzeiterinnerungen gehören zu einer Organisation und einem verifizierten
SSO-Subject. Sie speichern eine dauerhafte Tatsache, eine Einbettung,
Zeitstempel und die Herkunft der Quell-Conversation.

Die Runtime begrenzt jeden Subject auf 200 Memories. Durch das Löschen wird eine
Information aus zukünftigen Prompt-Injektionen und Memory-Suchen entfernt.

## Programmatische Anmeldeinformationen

Ein API-Schlüssel-Datensatz gehört zu einer Organisation und speichert einen
geheimen Hash, die Role, den Creator sowie den Revocation-Status. Das im
Klartext vorliegende Secret wird nicht gespeichert.

## Isolation

Der authentifizierte Zugriff auf die Konsole verwendet gegebenenfalls
Row-Level-Security. Service-Rollen-Pfade müssen eine explizite
Organization-Grenze hinzufügen.

API v1 verwendet die anhand des API-Schlüssels aufgelöste Organization. Es
akzeptiert keine vom Aufrufer ausgewählte Organization als Autorität.
