La identidad verificada y la memoria a largo plazo son entradas que las acciones
leen. No son etapas del enrutador, por lo que la imagen no las incluye.

`messageFlowCandidates` proporciona candidatos a ambos motores de enrutamiento.
Este límite evita que las condiciones objetivas generen resultados diferentes en
el enrutador.

El contexto de la conversación proporciona ejemplos semánticos para la
clasificación. No actúa como una puerta booleana independiente.

## Contexto vinculado a la identidad

Una puerta de SSO de Widget válida proporciona un sujeto con ámbito de
organización. Una afirmación verificada opcional añade un identificador legible
a ese sujeto.

Un endpoint de integración de API puede anclar un parámetro a
`{{identity.subject}}` o a `{{identity.claim}}`. El servidor rellena el valor
verificado después de validar la entrada de la herramienta.

El modelo no puede omitir ni anular un valor de identidad anclado.

En el primer turno de una nueva Conversation, el entorno de ejecución puede
inyectar hasta cinco recuerdos a largo plazo relevantes. Una herramienta de
búsqueda en la memoria integrada se encarga de la recuperación posterior.

Ambas rutas de memoria requieren que esté activado el conmutador Organization y
que haya un sujeto de SSO verificado.

## Atajo de cortesía

El flujo de interacción básico integrado puede gestionar un mensaje breve
únicamente de cortesía antes de la clasificación de intenciones. Un Flow
personalizado elegible anterior sigue teniendo prioridad.

El atajo no se activa después de una pregunta del asistente ni en el caso de un
mensaje que contenga una solicitud de información.

## Ruta proactiva

El elemento incrustado informa sobre la carga de la página, el tiempo de
permanencia y los eventos de apertura del chat. El servidor valida el
desencadenante configurado y el estado de entrega.

Un Flow proactivo contiene una acción Notification y ninguna condición. La
acción emite el contenido configurado sin realizar una llamada al modelo.

## Ejecución de la acción

Las acciones se ejecutan en el orden en que están almacenadas. Cada acción
devuelve partes de respuesta estructuradas o un efecto silencioso.

El trabajo generativo se mantiene dentro de Basic reply, Search knowledge, los
Follow-ups generados y las rutas de recomendación admitidas.

## Transferencia

Handover carga un asistente de destino publicado en la misma organización. Hace
pasar el mensaje del visitante por ese asistente de destino una sola vez.

La ejecución de destino ignora otro traspaso. Esta regla evita una cadena de
asistentes sin límite.
