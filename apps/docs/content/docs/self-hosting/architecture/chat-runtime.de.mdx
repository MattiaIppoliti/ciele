Verified identity und long-term memory sind Eingaben, die von den Actions
gelesen werden. Sie sind keine Phasen des Routers, daher lässt die Abbildung sie
aus.

`messageFlowCandidates` liefert Kandidaten an beide Routing-Engines. Diese
Grenze verhindert, dass objektive Bedingungen zu unterschiedlichen Ergebnissen
des Routers führen.

Der Gesprächskontext liefert semantische Beispiele für die Klassifizierung. Es
fungiert nicht als unabhängiges Boolesches Gate.

## An die Identität gebundener Kontext

Ein gültiges Widget-SSO-Gate liefert ein Subject mit
Organisation-Geltungsbereich. Ein optionaler verifizierter Claim fügt diesem
Subject einen lesbaren Identifier hinzu.

Ein API-Integrationsendpunkt kann einen Parameter an `{{identity.subject}}` oder
`{{identity.claim}}` pinnen. Der Server trägt den verifizierten Wert ein,
nachdem er die Tool-Eingabe validiert hat.

Das Modell kann einen gepinnten Identitätswert weder auslassen noch
überschreiben.

Beim ersten Zug einer neuen Conversation kann die Runtime bis zu fünf relevante
Long-Term Memories injizieren. Ein integriertes Tool zur Speichersuche deckt das
spätere Abrufen ab.

Beide Speicherpfade erfordern den Schalter „Organization“ und einen
verifizierten SSO-Subject.

## Tastenkürzel für Höflichkeitsnachrichten

Der integrierte Basic Interaction Flow kann eine kurze, rein höfliche Nachricht
vor der Intent Classification verarbeiten. Ein früherer, infrage kommender
benutzerdefinierter Flow hat weiterhin Vorrang.

Der Shortcut wird nicht aktiviert, wenn eine Frage des Assistenten gestellt
wurde oder wenn eine Nachricht eine Informationsanfrage enthält.

## Proaktiver Pfad

Das Embed erfasst Ereignisse wie Page Load, Dwell Time und Chat-Open. Der Server
validiert den konfigurierten Trigger und den Delivery-Status.

Ein proaktiver Flow enthält eine Notification-Aktion und keine Bedingungen. Die
Aktion gibt den konfigurierten Inhalt ohne einen Modellaufruf aus.

## Ausführung der Aktion

Aktionen werden in der gespeicherten Reihenfolge ausgeführt. Jede Aktion gibt
strukturierte Antwortteile zurück oder hat eine stille Wirkung.

Generative Arbeit bleibt innerhalb von Basic reply, Search knowledge,
generierten Follow-ups und unterstützten Empfehlungspfaden.

## Handover

Handover lädt einen veröffentlichten Ziel-Assistenten in derselben Organisation.
Es führt die Visitor-Nachricht einmal durch diesen Ziel-Assistenten.

Die Zielausführung ignoriert eine weitere Übergabe. Diese Regel verhindert eine
unbegrenzte Kette von Assistenten.
