Una distribuzione self-hosted viene configurata interamente tramite variabili di
ambiente. Copia `apps/web/.env.example` in `apps/web/.env.local` e inserisci i
valori di cui hai bisogno. Il file di esempio viene fornito con impostazioni
predefinite funzionanti per lo sviluppo locale, quindi su uno stack di database
locale la maggior parte di queste è già impostata per te.

## Database

Imposta entrambi e il livello dati passerà automaticamente dal negozio demo al
tuo database. Lasciali vuoti per rimanere in modalità demo.

| Variabile | Scopo |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | L'URL del tuo progetto Supabase. |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | La chiave anonima pubblica per l'accesso dal browser. |
| `SUPABASE_SERVICE_ROLE_KEY` | Chiave solo server per il runtime del widget e per le letture con privilegi. Non esporla mai al browser. |

Vedi [Database](/self-hosting/database) per il provisioning e le migrazioni.

## Provider di IA

Gli assistenti chiamano un provider di IA per generare le risposte. Fornisci
almeno una chiave della piattaforma oppure indica un qualsiasi endpoint
compatibile con OpenAI per l'esecuzione completamente locale.

| Variabile | Scopo |
| --- | --- |
| `GOOGLE_GENERATIVE_AI_API_KEY` | Chiave della piattaforma utilizzata quando un assistente non ha una connessione al provider per organizzazione. |
| `ANTHROPIC_API_KEY` | Provider aggiuntivo facoltativo. |
| `OPENAI_API_KEY` | Provider aggiuntivo opzionale. |

<Callout title="Run fully local, no cloud AI">
Set `OPENAI_COMPATIBLE_BASE_URL` and `OPENAI_COMPATIBLE_CHAT_MODEL` to route
answers through any server that speaks the OpenAI chat API — a local runner, a
self-hosted model server, or a gateway. Add `OPENAI_COMPATIBLE_EMBEDDING_MODEL`
(and `OPENAI_COMPATIBLE_EMBEDDING_DIMS`) to enable semantic knowledge search;
without an embedding model, knowledge search falls back to lexical matching. An
API key is only needed if your server enforces one.
</Callout>

Le organizzazioni possono anche importare le proprie chiavi dall'interno della
console: si tratta di una funzionalità del prodotto e non di una configurazione
di distribuzione.

## Segreti e operazioni

| Variabile | Scopo |
| --- | --- |
| `APP_ENCRYPTION_KEY` | Protegge le chiavi del provider per ogni organizzazione quando sono inattive (AES-256-GCM). Senza di essa, tali chiavi vengono archiviate come testo in chiaro contrassegnato con un avviso. Generane uno con `openssl rand -base64 32`. |
| `PLATFORM_OWNER_EMAIL` | Il primo utente che si registra con questa email diventa il proprietario della piattaforma. |
| `CRON_SECRET` | Segreto condiviso a protezione delle route API di manutenzione e cron. |

## Acquisizione della conoscenza (opzionale)

La pipeline di conoscenza per la scansione del sito web può utilizzare un
crawler esterno. Questi sono opzionali; in loro assenza, viene utilizzato il
crawler locale integrato.

| Variabile | Scopo |
| --- | --- |
| `APIFY_API_TOKEN` | Token per il provider di crawling di siti web basato su Apify. |
| `CRAWL4AI_BASE_URL`, `CRAWL4AI_API_TOKEN` | Un worker privato di Crawl4AI; entrambi sono necessari per poterlo selezionare e il token è solo per il server. |

<Callout type="warn" title="Review row-level security before shipping">
The database ships with permissive row-level-security policies suited to a demo.
Scope them to authenticated administrators before exposing a deployment to real
users.
</Callout>
