### What this shows

How the `ciele` CLI and the ciele MCP server connect to a deployment — SaaS
(`platform.ciele.app`) or self-hosted — and what stands between an API key and
the database. Both clients share one typed client (`@ciele/client`), one HTTP
surface (`/api/v1`), and one operations layer (`@ciele/ops`); the diagrams below
are the reference for `docs/api/connections.md` and the AI-client integration
guide.

### CLI: login and a mutating command

<Mermaid id="cli-flow" caption="ciele login validates before storing; a later command resolves credentials flag → env → config file, so CI never needs the file and a laptop never needs the env." source={"sequenceDiagram\n  participant U as You\n  participant CLI as ciele CLI\n  participant CFG as ~/.ciele/config.json\n  participant API as /api/v1 (SaaS or self-host)\n  U->>CLI: ciele login --key ciele_sk_… [--base-url …]\n  CLI->>API: GET /whoami (Bearer key)\n  API-->>CLI: { organizationId, role, keyId }\n  CLI->>CFG: save key + base URL (0600)\n  U->>CLI: ciele flows create <assistantId> --name \"Fees intent\"\n  CLI->>CLI: resolve key: --api-key → CIELE_API_KEY → config\n  CLI->>API: POST /assistants/{id}/flows\n  API->>API: key hash → org+role · capability edit · zod · #541 rule\n  API-->>CLI: 201 Flow JSON\n  CLI-->>U: table (or --json) · exit 0/1/2/3"} />

### MCP: an agent operating the Organization

<Mermaid id="mcp-flow" caption="The MCP server is a thin stdio adapter over the same client; read-only mode refuses mutating actions before any request leaves the process." source={"sequenceDiagram\n  participant A as AI client (Claude Code, Cursor, …)\n  participant M as ciele-mcp (stdio)\n  participant API as /api/v1\n  A->>M: initialize / tools list\n  M-->>A: 7 tools (identity, assistants, flows, knowledge, publish, inbox, improvements)\n  A->>M: tools/call manage_knowledge {action add_faq, …}\n  alt CIELE_MCP_READ_ONLY=1 and action mutates\n    M-->>A: error result — refused locally, zero network\n  else allowed\n    M->>API: POST /collections/{id}/faqs (Bearer key)\n    API-->>M: 201 / error envelope\n    M-->>A: JSON text content (or isError)\n  end"} />

<Callout id="key-facts" tone="decision">

Three properties every integration inherits, by construction: **(1)** the key's
Role is the only permission model — a viewer-tier key cannot mutate anywhere,
no per-client configuration involved; **(2)** SaaS and self-host differ only by
`CIELE_BASE_URL`; **(3)** `CIELE_MCP_READ_ONLY=1` is enforced inside the MCP
process, before any request leaves it — safe default for exploratory agents.

</Callout>
